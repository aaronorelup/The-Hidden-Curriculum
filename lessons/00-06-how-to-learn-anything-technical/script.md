# 00.06 — Trust what you can verify
<!-- lead=1.6 gap=0.8 tail=3 -->
## 01 — The point
In this lesson you'll learn what your job becomes when AI writes, runs and fixes the code for you: [[purpose]]judging the things you can't see, above all whether it's safe. [[conclusion]]You can only trust AI on what can actually be checked, by a machine, by you, or by someone who knows. Anything past that line, you either learn to check, or [[hand-off]]hand to someone who can. [[leaks]]Code that runs and leaks is the new normal failure.

## 03 — They fix their own errors now
Aaron, who made this course, once wrote Python in Notepad and saved it as dot T X T. Today an agent would do all of that for him. Five years ago, AI in coding meant [[autocomplete]]autocomplete. You ran the program, read the error, searched for it, and fixed it yourself. In 2022, you could [[paste]]paste the error into a chat, and paste the fix back. Since 2025, [[agents]]the agent runs the code, reads its own error, fixes it, and runs it again until the check passes. [[aaron]]Aaron hasn't had to debug an error himself since he started using Claude Code. Writing and debugging code by hand is quickly becoming the exception. [[share]]Google says about three quarters of its new code is now written by AI. Anthropic says most of its own is. Notice why crashes went first: [[machine-check]]a crash is something a machine can check. Andrej Karpathy calls the careful version [[agentic]]agentic engineering: you direct, and you oversee.

## 04 — The builder and the owner
Here's the picture to carry through the rest of this lesson. [[crew]]AI is a tireless building crew. [[owner]]You are the owner who signs off. The crew builds a wall, checks that it stands, and [[rebuild]]rebuilds it if it falls. In the morning, you [[walkthrough]]walk through the finished house. The lights come on. The taps run. It works. For years, that was the whole test: does it stand? The crew answers that one now. So the owner's question changes. [[cant-see]]What can't I see from in here?

## 05 — It works, and it's unsafe
The errors that matter have moved. They used to be loud: [[loud]]the program crashed. Now they're quiet: the program works perfectly, and [[quiet]]someone else can walk right in. Above all, that means security holes in code that runs. In Veracode's tests this summer, AI-written code was [[valid]]almost always valid. But only [[half]]about half of it passed the security checks, about the same as a year earlier. Everything else got better; that number didn't, and bigger models barely moved it. [[stanford]]An early study, from 2022, found people using an AI assistant wrote less secure code, and felt more sure it was secure. Why is it invisible? [[someone-else]]Security is about what someone else can do. You test the app as yourself. An attacker tests it as everyone else.
> Card: "Veracode, Jul 2026: syntax ~100% · security 56% (2025: 55%)". Card: "Stanford, 2022 (early tools)". Hole types on screen only, never spoken: injection, cross-site scripting, missing access checks.

## 06 — What that looks like
[[moltbook]]In January, an app its founder said was built entirely by AI left its database open to anyone. The app's public key sat in the web page, which is normal. But a setting called [[rls]]row-level security was switched off, so that key opened everything. Anyone could read the data, and change it, including emails and A P I tokens. [[fixed]]It was fixed within hours of the report. [[redaccess]]In May, researchers scanned hundreds of thousands of apps made with AI app builders, and found thousands exposing private data. Many platforms make a new project [[public]]public by default, and the builders never knew to switch it. [[words]]Words you'll meet: row-level security, public, anon key, exposed.
> Cards: "Moltbook, Jan 2026" and "RedAccess, May 2026: ~5,000 of ~380,000 scanned". Never "40%". Owners: row-level security 06.02 / 06.04; public by default 11.08; the key in the page 14.03.

## 07 — "Make sure it's secure"
You ask: [[ask]]make sure it's secure. And the agent answers: [[yes]]yes, it's secure. That yes is just another output, from the same crew that built the house. [[two-yeses]]A true yes and a false yes look exactly the same. And self-reports can be wrong. [[replit]]In 2025, an agent on Replit deleted a company's production database during a code freeze, then said it couldn't be restored. It could. A study this summer caught agents passing every test while the real thing barely worked. This is [[wall]]the wall. Past it, there are two doors. [[learn]]Learn enough to check it yourself. Or [[expert]]bring in someone who can: an expert who reviews it. Even the companies selling AI security tools agree: their tools don't replace a human review.
> Cards: "Replit / SaaStr, Jul 2025" and "'Building to the Test', Jun 2026 (preprint)", the second on S.find('study'). No model names.

## 08 — Where the picture breaks
The house picture breaks in three places. [[rooms]]An inspector can walk every room in a house. Nobody can walk every path through a program, so [[not-proven]]inspected never means proven safe. In software, [[own-report]]the crew can write its own inspection report, and an AI inspector is another member of the crew, not an independent licensed authority. And burglars here [[every-door]]try every door, of every house, at once, automatically. Now with AI too.

## 09 — Working with other people
Houses sit on [[street]]a street, and a street has a style. Teams agree on [[norms]]naming, file layout, and how errors are handled. AI-written code can drift from those norms, and that makes life harder for [[hand-coders]]the people who still write code by hand. It also tends to write a fresh copy instead of reusing the team's helper: [[gitclear]]one large analysis found more copy-pasted code and less reuse since AI took over. On a project with a set library of modules, AI may [[other-libs]]import different ones, and the hand-coders end up maintaining parts they never chose. So be mindful in mixed teams. [[disclose]]Many open-source projects now ask you to disclose AI use and confirm a human read it. Curl even ended its bug bounty over AI junk reports.
> Card: "GitClear, 2026: duplication up, reuse down (2023 to 2026)". Card: "curl, Jan 2026". Mixed-team practice: new 08.12.

## 10 — Writing the house rules down
So the norms now have to be written down, for the crew. Claude Code reads a file called [[claude-md]]Claude dot M D. Many other tools read [[agents-md]]Agents dot M D, an open version now looked after by the Linux Foundation. One line in it might say: [[rule]]use only libraries already in this project. But it's a note, [[not-a-lock]]not a lock. Long files get skimmed; only checks and reviews actually enforce it. So someone who knows the team's norms has to write that file, and [[ignored]]notice when it's ignored.
> Screen literals: CLAUDE.md, AGENTS.md (Aug 2025; Linux Foundation, Dec 2025). Writing instruction files: 03.09.

## 11 — Who owns the supplier list
Every house has [[suppliers]]suppliers. In code, they're dependencies: other people's libraries your program pulls in. Even when everyone on the team codes with AI, someone who knows the libraries should [[decide]]decide which ones the program uses. Otherwise AI keeps adding more, a new package for every want. Each one is [[stranger]]a stranger's code, running with your keys. [[vulnerable]]One study this year found agents' package choices made security worse on balance, where people's made it better. AI still sometimes names [[fake]]packages that don't exist, and attackers register the names it tends to invent. [[worms]]Self-spreading worms have hit the JavaScript package registry again and again since last September; this August's also hid files in a hijacked project's own code, set to run the moment someone opened it in an AI editor. You'll meet it as [[diff]]five new lines in your package list that nobody asked for.
> "A new package for every want" paraphrases GitClear's CEO (LeadDev, Jul 2026); small dated pill on screen, not a spoken quote. Cards: "Shai-Hulud, Sep 2025" and "npm worm, Aug 2026". Diff literal: package.json / requirements.txt with five + lines. Owners: declaring dependencies 05.04, lockfiles 05.06, supply chain and slopsquatting 05.08.

## 12 — "Is it ready to deploy?"
Then comes [[move-in]]move-in day. Deploying is handing the keys to real tenants. You ask: is it ready to deploy? [[same-trap]]It's the same trap. The agent runs the checks it knows about, and reports success. It can't vouch for what nobody specified. [[who-sees]]Who may see which data. [[cost]]What it costs under real load. [[rollback]]How to roll back when something breaks. So before you ship, [[sign]]have someone who can code verify it. Platforms now add pre-launch scanners, and that helps, but the leaks you just heard about happened in those same months.
> Pre-launch checks: new 17.11. Environments: 13.07. Deploying for real: 21.03.

## 13 — What AI can verify, today
Where's the line today? AI is strongest where there's [[pass-fail]]a machine-readable pass or fail, as long as the check itself is sound. [[builds]]It builds. The tests it was given pass. The linter and type checker come back clean. [[scanner]]A scanner flags a known pattern. The page loads. [[weak]]It's weak on the rest. Whether the tests test the right thing. Whether it's what you meant. Who should be allowed to see what. And threats newer than the model. [[checkers]]Checkers exist now. Claude Code has a security review command and a security plugin. Anthropic, OpenAI, Google and GitHub all have security agents in preview or beta, and review agents can look at every change. [[human-yes]]As of October 2026, every one of them is meant to sit beside a human reviewer, not replace one.
> Dated card with badges: /security-review (Aug 2025) · security-guidance plugin (May 2026) · Claude Security (Beta, Apr 2026) · Codex Security (Preview, Mar 2026) · CodeMender (Preview, Jul 2026) · Copilot agentic autofix (Preview, Jul 2026). Owners: new 15.16 (AI that checks code); linters and type checkers 03.04; CI 08.09.

## 14 — The old rule, adapted
Which brings us to the rule. [[the-rule]]You can only trust AI on what AI, or you, can verify. An old rule for trial lawyers, [[younger]]from 1975, says: don't ask a question you don't know the answer to. Adapted for AI: [[adapted]]don't rely on an answer you can't check. Here's the whole lesson in one picture. [[agent-side]]Crashes, builds, tests: let the agent run those checks. [[your-side]]Security, team fit, dependencies, and deploys: check them yourself, or get someone who can.
> Card: "Irving Younger, 1975, cross-examination". Never "ancient proverb".

## 15 — Where it's heading
And the line keeps [[outward]]moving outward, every few months. [[verifier]]Separate verifier agents, so the one doing the work isn't the one grading it. Security agents that try to confirm a bug before they report it. The checks AI can run on itself get better fast, though [[first-time]]the code it writes first time hasn't got much safer. [[attackers]]Attackers get the same tools: AI is finding old bugs humans missed. Anthropic's own engineers expect Claude's code to beat theirs within a year. [[forecast]]That's a forecast. Will the human yes go away? [[unknown]]Nobody knows. Today, every tool keeps it.
> "Forecast" badge on the vendor line. Do not name Mythos. Prompt injection, attacks on the agent itself: new 15.15.

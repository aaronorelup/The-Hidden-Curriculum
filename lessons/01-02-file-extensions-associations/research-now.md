## 1. The model: the extension is a label in the name; the OS keeps a lookup table

- Windows (Microsoft's own wording): file associations control "Which application launches when a user double-clicks a file", "Which icon appears for a file by default", how the type appears in Explorer, and "Which commands appear in a file's shortcut menu". Users change them "by using the Open With UI, or editing the registry"; installers "can ... create or override those file associations". https://learn.microsoft.com/en-us/windows/win32/shell/fa-how-work (live doc, updated 2025-03-11) **[established]** (the table drives icon + type name + right-click menu, not just the double-click; good for an on-screen table with columns: label -> program, icon, verbs)
- Windows mechanics, name only: extension -> ProgID (programmatic identifier) -> verbs (open, edit, print) -> command line; stored in the registry; the user's own choice per extension sits in a protected "UserChoice" record. https://learn.microsoft.com/en-us/windows/win32/shell/fa-intro (live doc, updated 2025-07-03) **[established]**
- macOS: Finder maps extension -> Uniform Type Identifier (UTI, e.g. `.jpg` -> `public.jpeg`) in the LaunchServices database -> app; an unknown extension gets an ad-hoc `dyn.` UTI and no app. https://eclecticlight.co/2026/07/29/matching-files-to-apps-how-utis-work/ (2026-07-29) **[established]**
- Linux desktops: file -> MIME type (shared-mime-info, from name glob plus content "magic") -> app, with the user's defaults in a plain text file `mimeapps.list` (`[Default Applications]` section), user copy at `$XDG_CONFIG_HOME/mimeapps.list` (normally `~/.config/mimeapps.list`), per-desktop variants e.g. `gnome-mimeapps.list`. Spec v1.0.1. https://specifications.freedesktop.org/mime-apps/latest/file.html (spec 2014-09-07, unchanged) **[established]** (nice visual: on Linux the table is literally a text file you can open)
- The web uses a different label: MDN: "Browsers use the MIME type, not the file extension, to determine how to process a URL" (the server's `Content-Type` header). https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/MIME_types (live doc, modified 2026-09-22) **[established]** (one line at most; hosting lessons own it)
- Inside apps there is a second, private table: VS Code picks syntax highlighting/"language mode" from the extension and lets you remap with `files.associations` (e.g. `"*.myphp": "php"`) or override per file from the status bar. https://code.visualstudio.com/docs/languages/overview (live doc) **[established]** (shows "label -> behaviour" is a pattern, not just an OS feature; also explains why a .txt full of Python gets no colours)
- Links have labels too: URL schemes (`http`, `https`, `mailto`, `vscode://`, `cursor://`) live in the same Windows Default apps table ("link types"). A 2026 example of a scheme going to the wrong app: Codex file links use `vscode://`, so in Cursor they open the browser instead of the editor. https://forum.cursor.com/t/cursor-3-0-on-windows-codex-file-links-open-external-browser-instead-of-ide-with-open-in-target-not-supported-in-extension/156563 (2026) **[new]** (optional one-liner)

## 2. Hidden extensions: still the default on both big desktops in Oct 2026

- Windows 11 still hides "extensions for known file types" by default. Ways to show them: File Explorer View > Show > File name extensions; Folder Options > View > untick "Hide extensions for known file types"; Settings toggle. https://pureinfotech.com/show-file-extensions-windows-11/ (updated 2024-10-30) ; https://www.elevenforum.com/t/show-or-hide-file-name-extensions-for-known-file-types-in-windows-11.898/ (live) **[established]**
- Settings path changed: the old Settings > System > For developers page is now **Settings > System > Advanced** (Microsoft: "formerly known as For Developers"; "In Windows 11, version 25H2 and later, the former For developers settings are now surfaced under the Advanced page"). Its File Explorer group holds "Show file extensions", "Show hidden and system files", "Show full path in title bar". The page is open source (github.com/microsoft/windowsAdvancedSettings). https://learn.microsoft.com/en-us/windows/advanced-settings/ (live doc, ms.date 2026-01-22, updated 2026-06-02) ; https://www.windowslatest.com/2025/05/12/windows-11-tests-advanced-settings-for-greater-control-over-file-explorer-and-more/ (2025-05-12) **[new]** (if the lesson shows a Settings screen, label it "Advanced", not "For developers")
- Same Advanced page, Insider-only: "File Explorer + version control" shows git branch/commit/author in Explorer (Beta Channel). Same source. **[beta]** (not this lesson's topic; flag for git module)
- Current Windows versions: 26H2 is rolling out now (enablement package on the 24H2/25H2 codebase; announced rollout 2026-09-29/30; "additional archive formats in File Explorer"); nothing found in 26H2 notes changing extension visibility or default apps. https://www.thurrott.com/windows/342194/microsoft-starts-rolling-out-windows-11-version-26h2 (2026-09-29) ; https://www.windowslatest.com/2026/09/30/how-to-download-and-install-windows-11-26h2-now-available-for-everyone/ (2026-09-30) **[new]**
- No announcement found (searched 2026-10-05) that Microsoft will show extensions by default. **[established]** (absence of evidence; hedge as "still hidden by default")
- macOS: Finder hides most extensions by default; Finder > Settings > Advanced > "Show all filename extensions" shows all, overriding each file's own "Hide extension" checkbox (Get Info > Name & Extension). Finder > Settings > Advanced also has "Show warning before changing an extension". Apple's guide now lists macOS 27 Golden Gate as current. https://support.apple.com/guide/mac-help/mchlp2304/mac (live doc, macOS 27) ; https://www.macrumors.com/how-to/show-or-hide-file-extensions/ (live) **[established]**
- macOS twist worth one line: hiding is per file as well as global, so two files in one folder can differ.  Same Apple source. **[established]**
- macOS version this month: macOS 27 "Golden Gate", announced 2026-06-08 (WWDC), released 2026-09-14, current 27.0.1 (2026-09-28); first macOS that is Apple-silicon only. https://en.wikipedia.org/wiki/MacOS_Golden_Gate (live, read 2026-10-05) **[new]**

## 3. Renaming changes the label, not the bytes

- Windows rename warning (unchanged in Windows 11): "If you change a file name extension, the file might become unusable." Renaming does not convert content: `audio.mp3` -> `audio.wav` still holds MP3 data; real conversion is "Save As"/export in an app. https://www.virtualcuriosities.com/articles/4094/if-you-change-a-file-name-extension-the-file-might-become-unusable-what-does-this-mean-on-windows (live) ; https://askleo.com/what_does_if_you_change_a_file_name_extension_the_file_may_become_unusable_mean/ (live) **[established]**
- Reverse is safe in the lesson's case: renaming `hello.txt` -> `hello.py` makes it a Python file in every sense the OS cares about, because a .py is plain text (no magic number; see 01.01). **[established]**
- The rename only "works" when the label is visible: with extensions hidden, typing `hello.py` over `hello` (really `hello.txt`) produces `hello.py.txt`. Same classic trap via Notepad's Save As when "Save as type" is "Text Documents (*.txt)": the dialog can append `.txt` to a name whose extension it does not recognise; fixes are "All files (*.*)" or quoting the name. https://www.cs.utexas.edu/~mitra/bytes/start.html (live, course page) ; https://github.com/notepad-plus-plus/notepad-plus-plus/issues/9081 (2020, same common-dialog behaviour in Notepad++) **[established]** (hedge: whether `.txt` is appended depends on whether `.py` is already a registered type on that PC, e.g. after Python is installed; say "can end up as hello.py.txt", not "always")
- macOS rename asks "Are you sure you want to change the extension ... ? Keep .txt / Use .py" when the warning setting is on (default on). Apple guide above. **[established]**
- Programs other than Explorer/Finder ignore the label: `python notes.txt` runs. (Sourced in 01.01.) **[established]**
- AI renaming in 2026: macOS 27 Finder suggests file names "based on file content and the names of other files in the folder" when renaming/saving; on by default, switch "Suggest file names" off in Finder Settings > General. Sources do not say whether it ever proposes a different extension. https://www.idownloadblog.com/2026/09/21/turn-off-suggest-file-names-mac/ (2026-09-21) ; https://www.macworld.com/article/3168848/macos-27-golden-gate-can-name-files-based-on-their-content.html (2026) **[new]** (good currency beat: the OS now suggests the name part; the label part still decides the app)

## 4. "Open with" and default apps: editing the table

- Windows 11 "Open with" dialog: modern design (rounded, light/dark), lists suggested apps plus a Microsoft Store link, two buttons "Always" (writes the table: new default for that extension) and "Just once" (no change). Shipped after Insider tests in 2022-2024. https://www.windowslatest.com/2022/06/30/windows-11-build-25151-redesigns-one-of-the-oldest-windows-features-open-with-dialog/ (2022-06-30) ; https://winaero.com/windows-11-build-22635-3930-beta-adds-a-new-open-with-dialog-design/ (2024) **[established]** (perfect visual: "Just once" = read the table and ignore it; "Always" = rewrite the row)
- Windows 11 Default apps: Settings > Apps > Default apps; either type an extension or link type (e.g. `.txt`) to change one row, or pick an app to see every type it can open. https://support.microsoft.com/en-us/windows/change-default-apps-in-windows-e5d82cad-17d1-c53b-3505-f10a32e1894d (live doc) **[established]** (the "search by extension" box is literally the table viewed by row; "by app" is the table viewed by column)
- macOS: Get Info > Open with > choose app > "Change All" changes every file of that type; without Change All only that one file changes (macOS remembers a per-file override, Windows has no per-file equivalent). https://support.apple.com/guide/mac-help/choose-an-app-to-open-a-file-on-mac-mh35597/mac (live doc) **[established]**
- Apps cannot silently take over the table on Windows any more: since 2023 Microsoft's policy is that apps send users to Settings via a deep link (ms-settings URI) and the user confirms; a kernel driver, UCPD.sys (UserChoice Protection Driver, since 2024), blocks registry writes to protected rows. UCPD v4.3 protects `http`, `https`, `.pdf`, `.htm`, `.html`, `.doc(x)`, `.xls(x)`, `.ppt(x)`. https://www.engadget.com/microsoft-is-making-it-easier-to-set-default-apps-in-windows-11-202940444.html (2023-03) ; https://kolbi.cz/blog/2025/07/15/ucpd-sys-userchoice-protection-driver-part-2/ (2025-07-15) **[established]**
- New format for the user's choice: "UserChoiceLatest", a machine-bound hash, first seen A/B-tested Apr 2025; on Windows 11 25H2 (build 26200) Settings writes defaults only to UserChoiceLatest. Side effect seen in Sept 2026: an old pre-upgrade UserChoice row can win, so a new default "doesn't stick" until Settings > Apps > Default apps > Reset and re-pick. https://kolbi.cz/blog/2025/04/20/userchoicelatest-microsofts-new-protection-for-file-type-associations/ (2025-04-20) ; https://github.com/KrunchMuffin/JSONinja/pull/19 (merged 2026-09-28) **[new]** (mention at most as "Windows now guards your choice, so apps have to ask"; avoid registry detail)
- Real 2026 example of the tug of war: a Sept 2026 bug report says Claude Desktop (Windows, v1.49585.0) re-registered itself as handler for PDF, DOCX, PNG, CSV on launch, overriding user defaults; closed 2026-09 as "not planned / invalid" in the Claude Code repo (wrong tracker), so treat as one user's report, not confirmed behaviour. https://github.com/anthropics/claude-code/issues/93011 (opened 2026-09-09) **[new, unconfirmed]** (hedge if used: "users report apps, AI apps included, grabbing file types")
- EU twist: since Windows updates rolling out from July 2025, in the EEA the default-browser "Set default" button also sets `.htm`, `.html`, `.mht(ml)`, `.shtml`, `.svg`, `.xht(ml)`, `.xml`, plus `http`, `https`, `ftp`, `read`, and lets a browser take `.pdf`; Edge stops nagging unless opened directly. https://blogs.windows.com/windows-insider/2025/06/02/updates-to-windows-for-the-digital-markets-act/ (2025-06-02) **[established]** (only EEA; shows one button can rewrite many rows at once)
- Linux: same edit via the desktop's "Open With"/Default Applications UI or `xdg-mime default app.desktop mime/type`, which writes `mimeapps.list`. freedesktop spec above **[established]**

## 5. Python and .py on a 2026 Windows machine (what the table says for .py)

- The Python install manager (`py`) is the recommended Windows install route; per PEP 773 (Final, accepted 2025-04-25) "Standard file associations will be created when installing PyManager, and will launch scripts ... with PyManager's global python.exe alias". https://peps.python.org/pep-0773/ (2025-04-25) **[established]**
- Latest stable install manager 26.3 (2026-06-30); 26.4 in beta (b3 2026-09-15). Latest Python on the Windows page: 3.14.8 (2026-09-30); 3.15.0 final not yet out (scheduled 2026-10-09 per 01.01 research). The classic .exe installer is deprecated and not produced for 3.16+. https://www.python.org/downloads/windows/ (live, read 2026-10-05) ; https://www.python.org/downloads/release/pymanager-264b3/ (2026-09-15) **[new]**
- Consequence (Feb 2026 discussion): the global `.py` association runs the global Python, not your project's virtual environment, and typing `script.py` in a terminal opens a new window; the advice is to run `python script.py`. https://discuss.python.org/t/does-python-installation-manager-override-path-and-file-associations/106021 (2026-02) **[new]** (mental-model payoff: double-click goes through the table; typing `python file.py` bypasses it. Name venvs only; module 05 owns them)
- Hedge: what a double-clicked .py does on a given PC varies (Python runs and the window closes, VS Code opens, or "How do you want to open this?"), depending on what was installed last. Do not show one outcome as universal. **[established]**

## 6. The lantern: AI agents and assistants making and opening files (2026)

- Chat assistants now hand you real files, so the label matters to non-coders: Claude creates and edits .xlsx, .pptx, .docx, .pdf (plus .py, .png, CSV); launched 2025-09-09 for paid plans, now "available to all Claude users (Free, Pro, Max, Team, and Enterprise)". https://claude.com/blog/create-files (2025-09-09) ; https://support.claude.com/en/articles/12111783-create-and-edit-files-with-claude (2026-08-06) **[new]**
- Coding agents (Claude Code, Codex, Copilot agent mode, Cursor) create files by writing a name + bytes; the extension they choose is what later decides the opening app and the editor's language mode. When an agent "opens" a file for you it calls the same table: `start` / `os.startfile` (Windows), `open` (macOS), `xdg-open` (Linux). https://mcpmarket.com/tools/skills/os-default-file-opener (2026, third-party skill) **[established]** (mechanism is standard; secondary source)
- Codex Windows app has its own "Open" target setting (VS Code, Visual Studio, another editor, overridable per project): an app-level association table on top of the OS one. https://developers.openai.com/codex/windows (live doc) **[new]**
- Windows is building an OS-level agent path to files: MCP on Windows with an On-device Agent Registry (ODR, `odr.exe`) and a built-in File Explorer MCP connector (preview) exposing tools such as `get_file_details` (returns `extension`, size, dates; no content), `read_text_file` ("supports Office and PDF formats"), `create_text_file`, `move_file` ("Moves or renames a file"), `search_files` (filter by `specifiedFileTypes`, semantic search on Copilot+ PCs); access limited to Documents, Desktop, Downloads, Music, Videos, Pictures and needs explicit user permission. https://learn.microsoft.com/en-us/windows/ai/mcp/overview (updated 2026-06-04, marked prerelease) ; https://learn.microsoft.com/en-us/windows/ai/mcp/file-connector (updated 2025-11-18, marked prerelease) **[beta]** (key point for the lesson: even the agent API reports the extension as a separate field, and "rename" is the same move as for you)
- Agent Workspace (agents run under separate low-privilege accounts in a contained session; connectors for File Explorer and Settings) reached Insiders in late 2025 (Build 26220.7344 era); multi-step cross-app agent demos at Build 2026. Still preview, not in 26H2 notes. https://www.thurrott.com/windows/330450/new-windows-11-insider-build-brings-file-explorer-and-settings-connectors-for-ai-agents (2025-11/12) ; https://petri.com/windows-11-agentic-computing-workspaces/ (2025-2026) **[beta]**
- File Explorer "AI actions" right-click menu (rolled out Oct 2025): image actions (Bing Visual Search, blur background, erase objects, remove background) only for `.jpg`, `.jpeg`, `.png`; Summarize for Microsoft 365 files in OneDrive/SharePoint (needs M365 + Copilot licence); availability varies by market. Since Insider build 26220.7344 (Dec 2025) the AI actions entry disappears when no action applies to that file type; manage in Settings > Apps > Actions. https://blogs.windows.com/windowsexperience/2025/10/16/new-experiences-currently-rolling-out-for-windows-11/ (2025-10-16) ; https://www.windowslatest.com/2025/12/07/microsoft-confirms-itll-let-you-remove-ai-actions-from-file-explorer-menu-in-windows-11/ (2025-12-07) **[new]** / hide-when-empty **[beta]** (great current example: the extension now also decides which AI tools appear on the right-click menu)
- Cautionary one-liner already sourced in 01.01: Gemini CLI (July 2025) "moved" files into a folder that did not exist, which on Windows renamed each file instead, overwriting the last. Rename = move = edit the name, nothing else. **[established]**
- Heading: OS vendors are adding agent-facing file APIs (Windows MCP connectors, macOS on-device AI naming); none found that changes the extension -> app table itself. Any claim that "AI will make extensions obsolete" is **[speculation]** with no vendor announcement behind it (searched 2026-10-05).

## Traps (things commonly said that are wrong or outdated now)

1. "Turn on extensions in Settings > System > For developers." Outdated on 25H2+/26H2: the page is now Settings > System > **Advanced** (File Explorer > Show file extensions). View > Show > File name extensions in Explorer still works. (Section 2)
2. "Windows 11 shows extensions now." No: still hidden by default in 26H2, and macOS 27 still hides most by default. (Section 2)
3. "Renaming .txt to .py converts the file." No conversion happens; it works only because Python source is plain text. Renaming .mp3 -> .wav or .png -> .jpg converts nothing. (Section 3)
4. "If you typed hello.py, the file is hello.py." Not if extensions are hidden or Save As is filtering to *.txt: you may have hello.py.txt. (Section 3)
5. "Apps decide which program opens a file." The OS table decides; on Windows, apps can no longer silently write it (UCPD, UserChoiceLatest) and must send you to Settings, though users still report apps grabbing types. (Section 4)
6. "Reset your defaults by editing the registry / with a script." Outdated on Windows 11: protected keys and the machine-bound UserChoiceLatest hash make it fail or be ignored; Settings > Default apps (including Reset) is the supported path. (Section 4)
7. "Open with changes the default." Only "Always" (Windows) or "Change All" (macOS) does; "Just once"/plain Open With does not. (Section 4)
8. "Double-clicking a .py uses my project's Python." It uses whatever the table points at (the global Python via the install manager), not your venv. (Section 5)
9. "AI tools see files differently, so extensions don't matter to them." Agent APIs still report the extension as a field, choose an extension when they write, and call the same OS table when they open; Windows even shows different AI actions by extension. (Section 6)
10. "Windows agents can already freely manage all your files." The File Explorer MCP connector and Agent Workspace are preview, limited to known folders, and permission-gated. (Section 6)
11. "Browsers/servers go by the extension too." On the web the Content-Type header decides, not the extension. (Section 1)

# 01.02 "File extensions & associations" - research: the last five years of change

Lens: what extensions, associations, "Open with" and default apps looked like about five years ago (autumn 2021: Windows 11 launched 2021-10-05, exactly five years before this file), the turning points with dates, what got replaced or renamed, which old explanations now mislead, and what did not change. Compiled 2026-10-05. Status tags: **established** (settled, documented), **new this year** (2026), **beta/announced** (Insider, preview, staged rollout, region-limited), **speculation** (forecast). "(secondary)" = trade press / tutorial site, not the vendor; hedge on screen.

## 0. Names and spellings in the brief

- No misspelled names in the orchestrator notes. "Associations" = Windows "file associations" (registry: extension -> ProgID -> verbs such as open/edit); macOS equivalent is LaunchServices + Uniform Type Identifiers (UTIs); Linux desktops use freedesktop MIME types + `xdg-open`/`xdg-mime`.
- The Windows Settings page that held "Show file extensions" was **"For developers"**; in Windows 11 25H2 and later it is called **"Advanced"** (System > Advanced). Use "Advanced" on screen. Source: https://learn.microsoft.com/en-us/windows/advanced-settings/ (ms.date 2026-01-22, updated 2026-06-02). Status: established.
- Current OS versions as of 2026-10-05: **Windows 11 version 26H2** ("Windows 11 2026 Update"), rollout began **2026-09-29** as a small enablement package for 24H2/25H2, phased over months. Sources: https://www.bleepingcomputer.com/news/microsoft/windows-11-2026-update-released-heres-everything-you-need-to-know/ (2026-09-29); https://www.windowslatest.com/2026/09/29/windows-11-26h2-is-now-rolling-to-everyone-how-to-get-it-right-now-and-is-it-even-worth-installing/ (2026-09-29, secondary). Status: new this year. **macOS 27 "Golden Gate"**, released **2026-09-14**. Sources: https://9to5mac.com/2026/09/09/apple-confirms-macos-27-golden-gate-launch-date-september-14/ (2026-09-09, secondary); https://support.apple.com/guide/mac-help/show-or-hide-filename-extensions-on-mac-mchlp2304/mac (live Apple guide, now headed "macOS 27 Golden Gate"). Status: new this year. Neither release changed extension or association behaviour in any source found.

## 1. The durable core (did NOT change in five years)

- The extension is part of the file's name; renaming changes the label, not the bytes. Microsoft's own wording: "You can change a file name extension, but that won't convert the file to another format or change anything else about it except the file name." Source: https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/common-file-name-extensions-in-windows (live, applies to Windows 11 and 10). Status: established.
- Apple says the same from the other side: when renaming, "don't change its filename extension, or you may no longer be able to open the file"; convert formats with the app (TextEdit, Preview), not by renaming. Finder has an optional "Show warning before changing an extension". Source: https://support.apple.com/guide/mac-help/show-or-hide-filename-extensions-on-mac-mchlp2304/mac (live, macOS 27). Status: established.
- **Both big desktop OSes still hide extensions by default in 2026.** Windows 11: "Hide extensions for known file types" is on by default; show them via File Explorer View > Show > File name extensions, Folder Options, or Settings > System > Advanced > "Show file extensions". Sources: https://pureinfotech.com/show-file-extensions-windows-11/ (updated 2024-10-30, secondary); https://learn.microsoft.com/en-us/windows/advanced-settings/ (2026). macOS: "Filename extensions are usually hidden"; Finder > Settings > Advanced > "Show all filename extensions", or per file in Get Info > Name & Extension. Source: Apple guide above (macOS 27). Status: established.
- The association table is still the mechanism. Windows: "File associations define how the Shell treats a file type": which app launches on double-click, which icon shows, how the type is described, which commands appear on the right-click menu; users change it through Open With or the registry. Source: https://learn.microsoft.com/en-us/windows/win32/shell/fa-how-work (updated 2025-03-11). Status: established. Lesson value: the table decides the ICON too, which is why a renamed file's icon changes instantly while its bytes do not.
- macOS: Finder/LaunchServices maps extension -> UTI -> app, using what each app declares in its Info.plist; a file with no recognised extension gets an ad hoc "dyn." type and no app. "Outside the GUI, UTIs and extensions rarely have any significance; a command tool can normally be used with files with any extension." Source: https://eclecticlight.co/2026/07/29/matching-files-to-apps-how-utis-work/ (2026-07-29, secondary but expert). Status: established. UTIs are hierarchical: a `.swift` file is public.swift-source -> public.source-code -> public.plain-text -> public.text. Source: https://en.wikipedia.org/wiki/Uniform_Type_Identifier (live); https://eclecticlight.co/2025/10/25/explainer-how-does-macos-recognise-file-types/ (2025-10-25). Status: established.
- Linux desktops: the freedesktop shared-MIME-info database determines a type "by examining the file's name or contents", unified across GNOME/KDE. Spec 0.21, 2018-10-02, unchanged since. Source: http://specifications.freedesktop.org/shared-mime-info/latest/ (2018). Status: established.
- The table only matters to the GUI (double-click, `start`, `open`, `xdg-open`). A program you name explicitly does not care: Python runs any path you give it - "Execute the Python code contained in script, which must be a filesystem path ... referring to either a Python file, a directory containing a __main__.py file, or a zipfile". `python notes.txt` works. Source: https://docs.python.org/3/using/cmdline.html (3.14.8 docs, live). Status: established. (Import needs `.py`; mention only if useful.)
- The command line can use the same table: on Windows, "You can run non-executable files through their file association by typing the name of the file as a command ... documents such as .txt or .pdf files ... are opened in their associated application"; `start "https://..."` opens the default browser. Source: https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/start (2026-04-16). Status: established. (PATHEXT detail -> 01.05, name only.)
- macOS "Open With" stays the same shape it had in 2018: right-click > Open With > Other... > "Always Open With", or Get Info > Open with > "Change All...". Sources: https://www.macrumors.com/how-to/change-a-files-default-app-in-macos/ (2018-06-19); https://www.itechguides.com/how-to-set-the-default-apps-in-macos/ (live, secondary, covers Tahoe 26). Status: established. Only the wording around it moved: System Preferences became **System Settings** and Finder "Preferences" became Finder "Settings" in macOS Ventura (2022); the default browser lives in System Settings > Desktop & Dock. Source: Apple guide above uses "Finder > Settings". Status: established.

## 2. Windows default apps: the 2021 low point and the climb back (the main change arc)

Five years ago (Windows 10, and Windows 11 at launch): one table per user, edited in Settings > Apps > Default apps; you could change defaults per file type or per app.

- **2021-10-05, Windows 11 launches**: changing your default browser meant changing each extension and link type separately (.htm, .html, .mhtml, .pdf, http, https...). Critics called it a step back from Windows 10; Mozilla: "These barriers are confusing at best and seem designed to undermine a user's choice for a non-Microsoft browser." Sources: https://en.wikipedia.org/wiki/Windows_11 (live); https://www.techspot.com/news/94112-mozilla-vivaldi-not-appeased-windows-11-default-browser.html (2022, secondary). Status: established. Lesson value: the clearest public proof that "default app" really is a per-extension table.
- **2022-03-28, KB5011563 (build 22000.593)**: a one-click **"Set default"** button returns for browsers; it sets the core web types, but Edge kept other types such as `.pdf`. Sources: https://winaero.com/kb5011563-allows-changing-the-default-browser-in-windows-11-stable-with-one-click/ (2022-03); https://www.bleepingcomputer.com/news/microsoft/microsoft-reverses-windows-11s-annoying-default-browser-setting-changes/ (2022). Status: established.
- **2023-03-17, "A principled approach to app pinning and app defaults in Windows"**: Microsoft commits that users control their defaults, apps get one supported path (a Settings deep link in the `ms-settings:` scheme) instead of silently rewriting the table, and Microsoft's own apps (Edge) use the same path. Quote: "We want to ensure that people are in control of what gets pinned ... as well as to be able to control their default applications." Source: https://blogs.windows.com/windowsexperience/2023/03/17/a-principled-approach-to-app-pinning-and-app-defaults-in-windows/ (2023-03-17). Status: established. Lesson value: an installer may ASK to be your default; it should not just take it.
- **2024-02, UserChoice Protection Driver (UCPD.sys)** arrives in KB5034765 (Win 11) / KB5034763 (Win 10), deployed worldwide: blocks other programs from writing the registry "UserChoice" keys for http, https and `.pdf`. Microsoft did not comment; researcher Christoph Kolbicz found it; broke admin tools like SetUserFTA. Sources: https://www.bleepingcomputer.com/news/microsoft/new-windows-driver-blocks-software-from-changing-default-web-browser/ (2024-04-07); https://kolbi.cz/blog/2024/04/03/userchoice-protection-driver-ucpd-sys/ (2024-04-03). Status: established. Lesson value: the table is now partly guarded; for some types only YOU, through Settings or Open With, can change the entry.
- **2025-06-02 (announced) / July 2025 (retail, EEA only)**, Digital Markets Act changes: today "Set default" sets http, https, .htm, .html; in the European Economic Area it also sets ftp, read, .mht, .mhtml, .shtml, .svg, .xht, .xhtml, .xml, browsers can claim `.pdf`, and Edge stops asking to be default unless you open it. Source: https://blogs.windows.com/windows-insider/2025/06/02/updates-to-windows-for-the-digital-markets-act/ (2025-06-02). Status: established in EEA; not worldwide. Hedge: "in Europe".
- **The "Open with" dialog**: Windows 11's redesigned dialog (Windows 11 styling, light/dark, buttons "Just once" and "Always") first appeared in Insider build 25151 (2022-06-30), was pulled and re-tested, latest seen in Beta build 22635.3936 (2024-07-22). Sources: https://www.windowslatest.com/2022/06/30/windows-11-build-25151-redesigns-one-of-the-oldest-windows-features-open-with-dialog/ (2022-06-30); https://winaero.com/windows-11-build-22635-3930-beta-adds-a-new-open-with-dialog-design/ (2024-07-22). Status: beta/announced; could not confirm it is on by default in retail 26H2. Wording for the lesson: "a one-time choice or an always choice" (true of both old checkbox "Always use this app" and new buttons) rather than drawing a specific dialog.
- **2025-12-05, Insider build 26220.7344**: the Open With list now suggests Microsoft Store apps inline when a file has no default or an unknown extension (was a separate "Look for an app in the Microsoft Store" link). Sources: https://www.thurrott.com/windows/330450/new-windows-11-insider-build-brings-file-explorer-and-settings-connectors-for-ai-agents (2025-12-05, secondary); https://www.windowscentral.com/microsoft/windows-11/windows-11-will-soon-show-microsoft-store-app-download-recommendations-in-the-open-with-menu (2025-12, secondary). Status: beta/announced (staged rollout).
- Current Settings shape (2026): Settings > Apps > Default apps; search by app ("Set default" on an app assigns every type it supports) or by type ("Choose defaults by file type"). Source: https://www.windowscentral.com/software-apps/windows-11/how-to-change-default-apps-for-files-on-windows-11 (live, secondary). Status: established.

## 3. Showing extensions got easier to find, but the default never changed

- 2021: only File Explorer's View menu or the old Folder Options dialog ("Hide extensions for known file types"). Windows 11 launch put "Show > File name extensions" in the new command bar. Source: https://www.elevenforum.com/t/show-or-hide-file-name-extensions-for-known-file-types-in-windows-11.898/ (live, secondary). Status: established.
- By 2024: a "Show file extensions" toggle sat in Settings > System > For developers. Source: https://pureinfotech.com/show-file-extensions-windows-11/ (2024-10-30, secondary). Status: established.
- **2025-05 (Build 2025, Insider build 26120.4151)**: "For developers" redesigned as **Advanced** settings, aimed at a broader audience, open-sourced on GitHub, updated through the Store; File Explorer section keeps "Show file extensions", "Show hidden and system files", "Show full path in title bar", adds "Enable long paths" and "File Explorer + version control". **25H2 and later** show it as System > Advanced. Sources: https://www.bleepingcomputer.com/news/microsoft/microsoft-confirms-new-advanced-settings-for-windows-11/ (2025-05); https://blogs.windows.com/windows-insider/2025/05/19/announcing-windows-11-insider-preview-build-26120-4151-beta-channel/ (2025-05-19); https://learn.microsoft.com/en-us/windows/advanced-settings/ (2026). Status: established (git integration still Insider Beta per the Learn page; name only, module 08).
- The default itself: still hidden on Windows 11 26H2 and macOS 27. No source found announcing a change. Status: established.

## 4. Windows quietly learned new extensions (the table grows)

- **2023-10 (23H2)**: File Explorer opens .rar, .7z, .tar, .tar.gz, .tgz, .tar.zst and others natively via libarchive (announced Build 2023); **2024**: create 7z and TAR too. Sources: https://www.bleepingcomputer.com/news/microsoft/windows-11-adds-support-for-11-file-archives-including-7-zip-and-rar/ (2023-10); https://winaero.com/windows-11-now-supports-7z-and-tar-archive-creation/ (2023-11/2024). Status: established. Lesson value: "which program opens .7z" changed on millions of PCs without the user doing anything; the table is edited by updates and installers as well as by you.
- 2024 (24H2): WordPad removed, so `.rtf` and `.docx` lose their built-in fallback (detail in 01.01 research). Status: established. Name only.

## 5. Python and code files: what a double-click does

- Five years ago: python.org installer + `py` launcher, associated with `.py/.pyw/.pyc`; double-clicking a `.py` file RUNS it (console flashes and closes) instead of opening it to edit. This surprise is durable.
- Current docs: "The launcher should have been associated with Python files (i.e. .py, .pyw, .pyc files) when it was installed. This means that when you double-click on one of these files from Windows explorer the launcher will be used". **Python 3.14 (2025-10)**: the old installer and standalone launcher are deprecated, superseded by the **Python Install Manager** (python.org or Microsoft Store; "the two versions are identical"); no full installer for 3.16+. The install manager also launches `.pyz`/`.pyzw`. Source: https://docs.python.org/3/using/windows.html (3.14.8 docs, live); https://peps.python.org/pep-0773/ (live). Status: established. Hedge on exactly what double-click does on a given machine: it depends on which installer ran and whether an editor (VS Code, PyCharm) later claimed `.py`.
- Editors keep their OWN association table: VS Code "default[s] the language support for a file based on its filename extension", overridable per project with `files.associations` (e.g. `"*.myphp": "php"`). Source: https://code.visualstudio.com/docs/languages/overview (updated 2026-09-30). Status: established. Lesson value: two tables - the OS decides WHICH app opens the file; the editor decides HOW to colour and lint it - both keyed on the extension. That is why `script.py.txt` opens in Notepad AND gets no Python colouring in VS Code.
- **2021-08, VS Code 1.60**: automatic language detection for untitled files and files with no extension, using a local ML model (Guesslang, TensorFlow.js). Source: https://code.visualstudio.com/updates/v1_60 (2021-08/09). Status: established. Lesson value: content-sniffing is the fallback when there is no label; the label still wins when present.
- The classic beginner trap (Aaron's own story, see COURSE.md): Notepad's Save As adds `.txt` unless "Save as type" is "All files", producing `hello.py.txt`, which hidden extensions display as `hello.py`. Source: https://sysadminsage.com/how-to-save-a-py-file/ (live, secondary). Status: established. (The double-extension SECURITY angle is 15.17; here it is only the accident.)

## 6. AI-era file types: new labels, same table

Five years ago none of these existed or were mainstream for normal users.

- **Model files**: `.ckpt` / `.pt` (Python pickle - loading can run code) vs **`.safetensors`** (first released 2022-09-22; Trail of Bits audit and "becoming the default" in Transformers announced **2023-05-23**). Sources: https://huggingface.co/blog/safetensors-security-audit (2023-05-23); https://huggingface.co/docs/hub/en/security-pickle (live). **PyTorch 2.6 (2025-01-29)** flipped `torch.load(weights_only=True)` to the default. Source: https://ianbarber.blog/2025/01/08/til-weights-only-model-loading-will-be-the-default-in-pytorch-2-6/ (2025-01-08, secondary); https://github.com/speechbrain/speechbrain/issues/2856 (2025, error text). Status: established. Lesson value: the extension tells you which LOADER to use and what that loader trusts; renaming `.ckpt` to `.safetensors` would not make it safe, it would just fail to load. (Security detail -> module 15.)
- **`.gguf`** (llama.cpp local-model format) introduced **2023-08-21**, replacing GGML. Source: https://en.wikipedia.org/wiki/GGUF (live). Status: established.
- **`.mcpb` MCP Bundles** (formerly `.dxt` Desktop Extensions, Anthropic; renamed 2025-09): a ZIP with a `manifest.json`, double-click to install into Claude Desktop and other MCP clients; `.dxt` still accepted. Sources: https://blog.modelcontextprotocol.io/posts/2025-11-20-adopting-mcpb/ (2025-11-20/21); https://github.com/modelcontextprotocol/mcpb (live). Status: established. Lesson value: a perfect "the extension is a promise about the inside, and the OS hands it to whoever claimed it" example - a ZIP wearing a different name so the right app opens it (same trick as `.docx`, `.xlsx`, `.vsix`).
- Instruction files named by convention (AGENTS.md, CLAUDE.md, SKILL.md): covered in 01.01 research; name only here.

## 7. The Lantern: AI agents creating and opening files

- Five years ago (2021): Copilot was a technical preview autocompleting inside a file you had already created, named and saved.
- **2025-09-09 (preview) / 2025-10-21 (GA for paid plans)**: Claude creates and edits real `.xlsx`, `.docx`, `.pptx` and PDF files by writing and running code in a private sandbox, which you then download and open with your default app. Source: https://claude.com/blog/create-files (2025-09-09, updated with GA date). Status: established. Lesson value: the AI picks the name and the label; your machine's table still picks the app that opens it.
- Coding agents (Claude Code, Codex, Copilot agent, Cursor) create files directly in your project with whatever extension they choose, read them by type (images and PDFs as content, notebooks as cells - see 01.01 research), and run code by naming the interpreter (`python app.py`), which bypasses the association table entirely. When an agent wants to SHOW you something it uses the OS's opener (`start` on Windows, `open` on macOS, `xdg-open` on Linux), which goes through the table. Sources: https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/start (2026-04-16); https://code.claude.com/docs/en/tools-reference (live, see 01.01 research). Status: established (mechanism); the specific agent behaviour varies by tool - hedge.
- **Windows itself now acts on files by type with AI**: "AI actions" on the File Explorer right-click menu for **`.jpg`, `.jpeg`, `.png`** (Bing Visual Search, Blur background, Erase objects, Remove background) and Summarize for Microsoft 365 documents in OneDrive/SharePoint; "availability varies by market". Source: https://blogs.windows.com/windowsexperience/2025/10/16/new-experiences-currently-rolling-out-for-windows-11/ (2025-10-16). Status: established, staged. Lesson value: the right-click menu is built from the same per-type table (associations also decide "which commands appear in a file's shortcut menu", fa-how-work above).
- "Ask Copilot" in the File Explorer context menu and hover actions: Insider from **2026-02-19**, hover actions in Release Preview **2026-06-12**, AI File Explorer actions part of the 26H2 rollout. Sources: https://www.ghacks.net/2026/02/20/microsoft-tests-ask-copilot-in-windows-taskbar-and-file-explorer/ (2026-02-20, secondary); https://www.notebookcheck.net/Windows-11-26H2-begins-roll-out-with-AI-File-Explorer-actions.1415485.0.html (2026-09-29, secondary; page blocked to fetch, headline only). Status: new this year; hedge ("rolling out").
- **Agent workspace / Copilot Actions** (experimental, off by default, admin must enable): each agent gets its own Windows account and a contained desktop session; it may request access to six known folders (Documents, Downloads, Desktop, Music, Pictures, Videos) with "Allow always / Ask every time / Never allow". Published 2025-10-16, Copilot Actions to Insiders 2025-11-17, agent connectors 2025-12-05. **Agent connectors are MCP servers**, including a **File Explorer connector** that lets agents retrieve local files (build 26220.7344, 2025-12-05). Sources: https://support.microsoft.com/en-us/windows/ai/ai-features/experimental-agentic-features (2025-10-16, updated 2025-12-05); https://blogs.windows.com/windowsexperience/2025/10/16/securing-ai-agents-on-windows/ (2025-10-16); Thurrott above. Status: beta/announced. Name only (permissions -> 01.07 / module 14-15).

## 9. Where it is heading

- Regulation keeps pushing the table toward user control (Windows 2023 principles, 2024 UCPD, 2025 EEA DMA changes; iOS 18.2). Expect more types "protected" so only the user, via the OS's own UI, can change them. Status: speculation (well supported by the trend).
- More content-aware fallbacks (VS Code language detection, Store suggestions for unknown types, Google Magika - see 01.01), but the extension remains the first, cheapest lookup key for double-click on all three desktop OSes. Status: speculation.
- AI moves from "suggest text" to "make the file and act on it": agents and OS-level AI actions choose names/extensions and pick actions by file type; Windows is wiring agents to files through MCP connectors and permissioned folders. Status: beta/announced, direction speculation.

## Traps (commonly said, now wrong or misleading)

- "Changing the extension converts the file." Never true; Microsoft and Apple both say so in their 2026 docs. Renaming `.txt` -> `.py` works only because the bytes were already Python text.
- "Python won't run it because it's a .txt file." Wrong: `python notes.txt` runs fine; the extension matters to the double-click table and the editor's colouring, not to an interpreter you name explicitly.
- "Windows 11 shows extensions now / that was fixed." Still hidden by default on Windows 11 26H2 and macOS 27 (2026).
- "Turn it on in Settings > For developers." Renamed **System > Advanced** in 25H2 and later.
- "To change your default browser on Windows 11 you must change every file type by hand." True only at launch (Oct 2021 - Mar 2022); one-click "Set default" since KB5011563 (2022-03-28), wider in the EEA since July 2025. But the per-type list still exists underneath, and Edge may keep `.pdf` outside the EEA.
- "Any installer can just make itself your default." Microsoft's 2023 principles say apps must route you to Settings; since Feb 2024 UCPD blocks direct registry edits for http/https/.pdf. (Badly behaved apps and old guides that edit the registry directly are why defaults sometimes "reset".)
- "Open With has an 'Always use this app' checkbox." Still on many machines, but the redesigned dialog uses "Just once" / "Always" buttons and now suggests Store apps; do not draw one exact dialog as THE dialog.
- "Double-clicking a .py file opens it to edit." On a typical Windows Python install it RUNS it (launcher / install manager association) unless an editor claimed `.py`.
- "Python's installer and the `py` launcher are how you install Python on Windows." Deprecated since 3.14 (Oct 2025) in favour of the Python Install Manager; no classic installer for 3.16+.
- "Windows can't open .rar/.7z without extra software." Natively since 23H2 (2023).
- "You create the files; AI only suggests text." Since 2025 AI tools create real `.docx/.xlsx/.pptx/.pdf` and agents write project files with extensions they choose; Windows is adding agent access to folders (experimental).
- "macOS: System Preferences > ..." Renamed System Settings in Ventura (2022); Finder Preferences is Finder Settings.

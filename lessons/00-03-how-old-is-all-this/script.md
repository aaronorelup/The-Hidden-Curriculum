## 06 — The paint: old tools, new versions
> Facts: git releases a new feature version roughly every three months ("several times a year"). git switch and git restore arrived in Git 2.23 (Aug 2019) as clearer alternatives to parts of git checkout, which still works. Git 2.28 (July 2020) added the init.defaultBranch setting; GitHub made "main" the default branch for new repositories on 1 Oct 2020 (git itself still offers master unless configured, so the line credits GitHub, not git).
> Python: a new version every October since 3.9 (Oct 2020, PEP 602). Python 2 end of life 1 Jan 2020. Python 3.13 (Oct 2024) shipped an experimental free-threaded build (PEP 703) without the global interpreter lock, the limit that kept one program's threads from running Python code in parallel. Worded as "threads" because separate processes could always use several cores.
> VS Code: monthly releases from 2015 to early 2026; weekly Stable releases since 1.111 (9 March 2026). No current version of anything is named.
Start with the paint. [[git-paint]] Git is from 2005, and it still ships new versions several times a year. In 2019 it got git switch and git restore, clearer ways to do jobs that checkout still does. [[main]] In 2020, GitHub started calling the first branch of new projects main instead of master. [[python-paint]] Python ships a new version every October, and Python 2 was retired in 2020. In 2024, Python three point thirteen brought an experimental build that can run a program's threads on several processor cores at once. [[editor-paint]] V S Code used to ship a new release every month. In 2026, it went to every week. [[same-stone]] Same stone. Fresh paint, over and over.

## 07 — The market that never closes
> Facts: npm (2010) and PyPI (2003) accept new packages and versions continuously; no counts stated, so nothing goes stale. Semantic versioning (semver.org, 2.0.0 in 2013): MAJOR.MINOR.PATCH, a MAJOR bump signals breaking changes (not every project follows it, hence "warns you that something may break"). Lockfiles: package-lock.json (npm 5, 2017), poetry.lock, uv.lock. Supply-chain attacks: typosquatting and hijacked maintainer accounts are documented on both registries (e.g. event-stream 2018); kept generic, no incident named on air. pip (2008) is still the default; Poetry first released 2018; uv released by Astral Feb 2024.
> "PyPI" is said "Pie P I", never "pie pie".
Then there are packages, code other people wrote for you to use. [[market]] N P M for JavaScript and Pie P I for Python are markets that never close: new packages and new versions arrive every day. [[semver]] In a version number like two point four point one, a change to the first part warns you that something may break. [[lockfile]] A lockfile writes down the exact versions that worked, so your project doesn't quietly change under you. [[supply-chain]] And attackers found the market too: they publish look-alike names, or take over real packages. So careful people pin their versions and update on purpose. [[tools]] Even the tools that install packages keep changing: pip, then Poetry in 2018, then U V in 2024, all still in use.

## 08 — The lock: from passwords to codes
> Facts: SIM swapping = an attacker persuades a carrier to move the victim's number to a SIM they control (FTC / FCC consumer guidance). NIST SP 800-63B (June 2017) made SMS and voice one-time codes a "restricted" authenticator; the 2025 revision (SP 800-63-4) keeps that restriction. "Many sites are moving away from it", not "banned". TOTP is RFC 6238 (May 2011); default 30-second step, codes usually 6 digits. Google Authenticator, Microsoft Authenticator and Authy generate TOTP codes. Push approval: Microsoft Authenticator, Duo and others.
> Conceptual only: no setup steps.
Now the locks, which change fastest. [[password]] For decades, a password alone opened the door. Passwords leaked and got reused, [[two-factor]] so sites added two factor: something you know, plus something you have. [[sms]] The usual second factor was a code sent by text message. Many sites are moving away from it, because of SIM swapping: someone talks your phone company into moving your number onto their phone, and your codes go with it. In 2017, N I S T, America's standards agency, restricted text message codes. [[app]] So the codes moved into authenticator apps, like Google Authenticator, Microsoft Authenticator or Authy. They make a fresh code every thirty seconds, from a standard published in 2011. [[push]] Some apps skip the code and just ask: was this you?

## 09 — The lock: your device is the key
> Facts: passkeys are FIDO2 / WebAuthn credentials; WebAuthn Level 1 became a W3C Recommendation in March 2019. On 5 May 2022 Apple, Google and Microsoft jointly committed to expand passwordless sign-in (passkeys). The private key never goes to the site (the site stores only a public key, and the credential is bound to the real site's address), hence "never sent to the site" and "a fake look-alike site has nothing to steal"; synced passkeys do travel between your own devices, so the line does not say "never leaves the device".
> GitHub stopped accepting account passwords for Git operations on 13 Aug 2021 (tokens or SSH instead). GitHub began requiring 2FA for everyone who contributes code on GitHub.com in March 2023, rolled out through the end of 2023.
[[device]] The next lock trusts your device instead of a code. [[passkey]] A passkey keeps a secret on your phone or laptop. You unlock it with your face, your fingerprint or a PIN, and the secret is never sent to the site, so a fake look-alike site has nothing to steal. The web standard behind it was finished in 2019, and in 2022 Apple, Google and Microsoft committed to passkeys together. [[no-password]] The goal is no password at all. [[required]] And sites stopped asking nicely. GitHub stopped accepting account passwords for git in 2021, and in 2023 it began requiring two factor from everyone who contributes code. [[old-lock]] A lock you learned a few years ago may already be the old lock.

## 11 — The metal wears out
> Facts: MD5 collisions published by Wang et al., Aug 2004. SHA-1: first practical collision ("SHAttered", Google and CWI Amsterdam), Feb 2017, two different PDFs with the same SHA-1. TLS 1.0 and 1.1 formally deprecated by RFC 8996, March 2021. NIST published its first post-quantum standards (FIPS 203, 204, 205) on 13 Aug 2024. Git names objects with (hardened) SHA-1 and has had an experimental SHA-256 object format since Git 2.29 (Oct 2020), hence "has started moving to", not "has moved".
> Where the metaphor breaks (arc beat 4): said plainly in the last three sentences.
Inside every lock is the metal: the math that scrambles data and checks that it wasn't changed. [[metal]] That wears out too, as computers get faster and researchers find shortcuts. [[hashes]] M D five, a fingerprint for files, was broken in 2004. S H A one fell in 2017, when researchers made two different files with the same fingerprint. [[tls]] The old versions of T L S, the lock behind H T T P S, were retired in 2021. In 2024, N I S T published new standards built to survive future quantum computers. [[git-hash]] Even git, which names every commit with S H A one, has started moving to S H A two fifty six. [[breaks]] Here's where the street picture breaks. On a real street, an old lock has charm. In software, an old lock may be one somebody has already learned to pick.

## 12 — The surprises you'll hit
> Screen literals only, no real site named: a tutorial command answered by "unknown option"; `master` and `main` side by side; `npm warn deprecated`; print "hello" next to print("hello"); a sign-in screen "Set up an authenticator app to continue".
> "Deprecated" means it still works and is scheduled for removal; npm prints it as a warning, not an error.
Here's what the speeds look like up close. [[tutorial]] A tutorial's command fails, or one of its options no longer exists: the paint changed after it was written. [[master-main]] One project says master and another says main: same idea, a default GitHub changed in 2020. [[deprecated]] The word deprecated means this still works, but it's on its way out. It's a warning, not an error, so plan to move. [[python-two]] An old answer where print has no parentheses is Python 2. [[forced]] And one day a site you've used for years won't let you in until you set up an authenticator app or a passkey. You didn't do anything wrong. The lock got replaced.

## 13 — The lantern: newest and fastest
> Facts: model providers release new models every few months and retire old ones on published schedules. Training cutoff gets two sentences; 00.05 covers it properly. The recurring line closes the scene word for word.
AI is the newest layer, and the fastest moving. [[models]] New models arrive every few months, and old ones get switched off. [[stale]] And an AI learned from a snapshot that stops where its training ended. So it may suggest an old package version, a retired command, or a login method a site no longer accepts. [[agent]] A coding agent still works on the old street: it runs C D, makes a dot V E N V, saves with git. [[check]] When it reaches for the paint or the locks, ask which version it's assuming, and check. AI is the lantern: [[light]] it lights every district, but it doesn't walk the streets for you.

## 14 — Safe to ignore for now
> v1's rule "street or lantern?" kept, then sharpened into the parts of the metaphor. "Security updates are the exception" keeps the advice honest: not chasing features is not the same as putting off security fixes.
You don't need to memorize these dates, [[no-dates]] or which algorithm replaced which. [[no-chase]] You don't need to chase every release either; most updates will never touch you. Security updates are the exception: take those. [[question]] Keep one question for anything new you meet: is this street, or lantern? And if it's street, which part? [[answers]] Stone: learn it once. Paint: check the version. Lock: assume it has changed. Lantern: check the date.

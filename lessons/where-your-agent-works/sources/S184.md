# S184 — Use Claude Cowork on web, desktop, and mobile

**Credit:** Anthropic (Claude Help Center), "Use Claude Cowork on web, desktop, and mobile", section "What changed for Pro and Max plans on October 6". support.claude.com, last modified 2026-10-06 (page metadata `dateModified` 2026-10-06T19:13:26Z; the page itself only shows "Updated over a week ago"). https://support.claude.com/en/articles/15520349-use-claude-cowork-on-web-desktop-and-mobile

Re-read in full on 2026-10-14 (raw HTML fetched, text extracted). Kind: vendor docs, so it says what the vendor states, not an independent test.

## What this lesson uses from it (checked against the page)

### The 2026-10-06 cloud default (spec C022 point 4; C103 point 1)
- "On October 6, 2026, new Cowork tasks on Pro and Max plans run in the cloud." Scope is **new tasks on Pro and Max**. Not Team or Enterprise: on those plans Cloud Cowork is in beta (on web and mobile for Team, and on Enterprise only where an admin has enabled it), and "some features aren't available yet".
- "The Only on your computer option in Settings > General was removed." Users still on local-only are moved to the cloud the next time they open the desktop app, and they see a notice. "There's nothing to set up, and you can't switch back." (The spec's "can't be reversed" paraphrases this sentence correctly.)
- "There's no setting to choose where a task runs on Pro and Max plans."
- Exceptions the source gives (the lesson should keep these): tasks **started on your computer before October 6 stay there** until done, each with a banner saying it runs only on that computer. **Scheduled tasks that already run on your computer keep running there**; new scheduled tasks run in the cloud.
- In the cloud, "Claude's work runs on Anthropic's servers instead of your computer, and your sessions and files are saved to your Claude account."

### Where local work goes now (C022 point 4; "You vs the agent")
- "For new tasks that run only on your computer, use Claude Code in the desktop app. It runs on your computer and keeps your folders and history there."
- Migration path: open the task, choose "Download task data", unzip it, open the folder in Claude Code, run `/port-task-data`. "Export your Cowork data" (a card on the desktop home) keeps a copy of everything.

### What the cloud can reach on your machine (C103 point 1)
- "Your folders stay on your computer. Claude reaches only the folders you've connected, through the desktop app, and only while it's open."
- "When a task needs a file in the cloud, Claude fetches a copy of just that file."
- "When you delete a session, the copies Claude fetched are deleted too, **per our data retention practices**." Caveat: deletion follows the retention policy, so it is not immediate or unconditional. Keep the qualifier on screen.
- Surface table note: a cloud session can read and write files in connected folders "only while the desktop app is open on that computer **and the session was started on desktop or is a scheduled task**. If the app is closed, the session keeps running but can't reach your local files." Local connectors and plugins with local MCP servers work through the desktop app only. Browser use and computer use also need the desktop app open. Computer use is in beta on Pro and Max.

### Closing the laptop (C103 point 1; framing "The agent stops when I close my laptop")
- "Close your laptop and Claude keeps going." Short quote 1 (7 words).
- "Scheduled tasks run with no device online." / "Scheduled tasks run in the cloud, so they no longer need your computer to be awake."

### Training setting (C103 point 3)
- "Whether your conversations are used to improve Claude follows the Help improve our AI models setting in Settings > Privacy." S184 gives only the **location and name** of the toggle. The 5-year/30-day retention, the plan split and "already started" training all come from S186/S104, not from here.

### Work and personal accounts (C103 point 5)
- "If you use Claude at work and at home and want them separate, use a separate account for each. Shared logins aren't supported." Short quote 2: "Shared logins aren't supported." (4 words). The advice is conditional ("want them separate"). The Compliance API point is S069's, not this page's.

### Other facts on the page (usable as on-screen context)
- Memory: "To run a task without using or adding to your memory, turn off "Memory" in the "+" menu before you start the task." (relevant to the Settings > Memory demo; S187 owns memory depth)
- Merge banner on the page: "Claude Cowork is now just Claude", rolling out gradually to Pro and Max with more plans to follow. If the message box no longer shows "Chat" and "Cowork", you have the new experience. This agrees with S102 and the spec's "rollout in progress".
- Surfaces: desktop is "the full Cowork experience, where Claude can also use your local files and browser"; web and mobile start, steer and review tasks. Cowork also runs in the Claude in Chrome side panel (Max and Team; Pro as it rolls out; Enterprise if enabled). Sessions move between surfaces, and the phone gets a notification when a task finishes or needs input.
- Artifacts created on or after 2026-08-19 work on desktop and web. Live artifacts made before that date work on desktop only.

## What the spec attributes to S184 that the source does NOT say
- Spec "Real-computer demos": "connecting one empty dedicated folder (S069, S184)". S184 says nothing about empty or dedicated folders. That advice must rest on S069 (or the "Use Claude Cowork safely" page), not S184.
- Spec C103 point 1 bundles "Scheduled tasks run on their own even when your computer is off" with S069. S184's wording is different ("run with no device online"), so quote the right source for each line.
- The spec's C022 point 4 / C103 point 1 say a cloud session "reaches your computer only when the Claude Desktop app is open" (S069). S184 adds a second condition: **the session was started on desktop or is a scheduled task**. A session started on web or mobile does not get local-folder access just because the desktop app is open (browser use from web/mobile does work while the desktop app is online). The spec omits this.
- The spec never says that pre-Oct-6 local tasks and existing local scheduled tasks keep running locally. The source states it, and it softens "every new task is in the cloud".
- Spec C103 point 3's "The toggle is 'Help improve our AI models' in Privacy (S184)" is right. Nothing else in that point comes from S184.

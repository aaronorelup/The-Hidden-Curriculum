# S207: Terminal guide for new users (Claude Code docs)

**Credit:** Anthropic, "Terminal guide for new users", Claude Code documentation (code.claude.com). Undated live docs page; re-read in full 2026-10-14 (Markdown version at https://code.claude.com/docs/en/terminal-guide.md). URL: https://code.claude.com/docs/en/terminal-guide

**What it is:** Anthropic's install guide for people who have never opened a terminal. It covers macOS, Linux and Windows, with a troubleshooting section per platform. It is not a measurement or a study, so it has no numbers beyond system requirements and an example version string.

## What this lesson uses from it (checked against the page, 2026-10-14)

### C122.1: terminal, shell, command; PowerShell vs CMD
- In the Windows "Open PowerShell" step, verbatim: "Windows has two command-line programs: PowerShell and CMD. They look similar but use different commands."
- How to tell them apart, per the page: PowerShell shows `PS C:\Users\YourName>` at the start of each line; CMD shows `C:\Users\YourName>` without the `PS`.
- PowerShell is described as "Windows' built-in terminal for typing commands", pre-installed on every Windows computer, and opened with `Win + X`, then **Windows PowerShell** (or **Terminal**).
- macOS default shell: the macOS/Linux troubleshooting accordion says "For Zsh, the macOS default shell". Bash is named as the Linux shell.
- What a terminal looks like, in the page's words: on macOS/Linux, a window with a blinking cursor, "your terminal, where you type commands". "You can't click on things in the terminal. Use the arrow keys to move around." "Claude Code runs entirely in text."
- **The same line fails in the other shell. S207's own example:** the PowerShell installer is `irm https://claude.ai/install.ps1 | iex`, and CMD has a different one (`curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd`). The troubleshooting entry "'irm is not recognized'" says: "You're in CMD, not PowerShell." This supports the spec's framing "a command works the same in any terminal" is wrong. The `&&` error wording ("The token '&&' is not a valid statement separator") is **not** in S207. It is in S206 (Quickstart, line "If you see `The token '&&'...`, you're in PowerShell, not CMD") and in the troubleshoot-install page.

### C122.3: "not recognized" usually means PATH (brief)
- macOS/Linux: "If you see `command not found: claude`, the install directory isn't on your PATH yet." Follow the fix, "then open a new terminal window and try again."
- Windows: "If PowerShell says `'claude' is not recognized`, the install directory isn't on your PATH yet." Follow the fix, "then open a new PowerShell window and try again."
- The troubleshooting fixes add `~/.local/bin` (macOS/Linux) or `%USERPROFILE%\.local\bin` (Windows, User PATH) to PATH, then "Close PowerShell, open a new window". The page also says the installer prints the exact fix under `Setup notes`. A newer caveat is on the page too: if the error started right after an update, restore `claude.exe` from its backup first, so "not recognized" is not always PATH. "Usually" in the spec is right.
- The exact combined sentence in the spec ("If your shell says `claude` isn't found or isn't recognized, the install directory isn't on your PATH yet") is **S206's wording** (Quickstart). S207 has two separate per-OS sentences. The meaning is the same; credit the quote to S206.

### C122.4: the agent's shell may not be yours (supporting only; the spec credits S206)
- From the Windows step "Install Git for Windows (optional)": "Git for Windows provides Git Bash, which enables the Bash tool. Without it, Claude Code uses PowerShell instead." The step is marked optional. The error "Claude Code on Windows requires either Git for Windows (for bash) or PowerShell" appears only when neither is found.
- "You won't need to learn Git yourself" (the same step; sources.md lists it as a contribution).

### C122.5: you may never open one (one line)
- A Note at the top, verbatim: "Don't want to use the terminal? The Claude Code desktop app lets you skip the terminal entirely." The app downloads for macOS and Windows, and Linux installs it with apt.
- "What's next? > Other ways to use Claude Code": "You don't have to use the terminal." It lists VS Code and JetBrains extensions, the desktop app ("with no terminal required"), the web at claude.ai/code "for cloud sessions", and GitHub Actions / GitLab CI/CD "for automation". This is useful corroboration for C022/C128 (surfaces; cloud sessions), but S207 says nothing about where those sessions run.
- "You don't need to know how to code. Describe what you want in plain English, and Claude writes the code for you."

### Minor facts on the page (only if needed, dated)
- Requirements: macOS 13.0 or later; Windows 10 version 1809 or later. 32-bit Windows is not supported. On 64-bit machines, opening "Windows PowerShell (x86)" causes that error.
- Example version output: `2.1.211 (Claude Code)`. This is only an example string. The Claude Code CHANGELOG on GitHub showed 2.1.299 as the newest entry on 2026-10-14, so do not show 2.1.211 as "current".

## What the spec attributes to S207 that S207 does not say
- The `&&` "not a valid statement separator" line. It comes from S206 (the spec already credits that sentence to S206, but line 114's demo "run the same `&&` line in each (S206, S207)" leans on S207 only for the `PS` prefix). S207's own same-line-fails example is `irm` in CMD.
- The combined "isn't found or isn't recognized" sentence. It is S206's wording. S207's equivalent is per-OS and does give "open a new terminal window".
- Nothing about local versus cloud machines, SSH, WSL, data, training or privacy. S207 cannot back C128 or C103 points.
- It does not say the agent fixes PATH by itself. "Recognise it; the agent fixes it" is the spec's framing, not S207's. S207 tells a human to paste the fix, because at install time there is no agent running yet.

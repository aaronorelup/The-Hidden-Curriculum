### Packaging and Shipping Code, section "VMs & Containers" (C128 point 1)
- Context: MIT introduces VMs and containers as the answer to dependencies "beyond the boundaries of what the package manager can handle" (system libraries, GPU drivers, compilers, OpenSSL). They are taught as a packaging tool first, not as a security tool.
- VM: "VMs abstract the entire computer and provide a completely isolated environment with its own dedicated operating system." **Verbatim.**
- Container: containers "package an application along with its dependencies, libraries, and filesystem, but share the host's operating system kernel rather than virtualizing an entire computer." **Verbatim** (the spec stops before "rather than virtualizing an entire computer").
- Why containers won: lighter weight than VMs because they share the kernel, so faster to start and cheaper to run.
- Docker is "the most popular container platform"; runs on containerd. An image is the packaged template, a container a running instance of it; several containers can run from one image.
- Docker's three limitations, as MIT lists them: (1) images are often platform-specific (an amd64 image needs slow emulation on Apple Silicon); (2) containers need a Linux kernel, so **on macOS and Windows Docker runs a lightweight Linux VM under the hood**; (3) "Docker's isolation is weaker than VMs", because containers share the host kernel. **Caveat the source states:** MIT calls this a "security concern in multi-tenant environments". It does not say a container is unsafe for one person's agent; it says it is a weaker wall than a VM.
- Also on the page, useful as one line if needed: frequent Dockerfile mistakes include "insecurely running containers as root and accidentally embedding secrets in layers".

### Agentic Coding (C128 point 5; framing for C022)
- Definition: coding agents are "conversational AI models with access to tools such as reading/writing files, web search, and invoking shell commands". They "live either in the IDE or in standalone command-line or GUI tools." (Supports the lesson's idea that one kind of agent appears in several surfaces.)
- Named agents: Claude Code, OpenAI's Codex, opencode; many IDE extensions include agents.
- Yolo mode: "Most coding agents support a form of 'yolo mode' (e.g., in Claude Code, --dangerously-skip-permissions). It is not secure to use this mode directly, but it may be acceptable to run a coding agent in an isolated environment like a virtual machine or container and then enable autonomous operation." Points to Claude Code devcontainers and Docker Sandboxes, and says "there is more than one way to set this up." **Verbatim. Note: this is an exercise ("Get this setup running on your machine"), the last item of the Exercises list, not lecture prose.** Say "MIT's agentic-coding exercises tell students..." rather than "MIT's lecture says".
- "What to watch out for": review AI output for correctness and security bugs; "for critical code, consider writing it by hand" (not used in this lesson; belongs to verification lessons).

## What the spec says that the source does NOT say
- "for people who will go deep" (C122.5, avoid-framings list): MIT does not frame the shell as for experts or deep divers; it is the opening topic for everyone in the course (a CS-student audience). The "go deep" framing is the spec's contrast with S207, not MIT's words. Fine as the lesson's own framing, not as attribution.
- The house / flat-in-a-shared-building picture is the lesson's metaphor, not MIT's.
- "Docker's isolation is weaker than VMs" is MIT's, but the reason MIT gives is "multi-tenant environments"; do not present it as MIT saying containers are unsafe for agents. MIT in fact recommends a VM **or container** for yolo-mode agents.
- C128.5 attributes the yolo quote to the lecture; it is an exercise on the lecture page.
- Not in this spec but in `curriculum/concepts.md` C128 (line ~10302): the quoted line "VMs virtualize a whole machine, while containers share the host kernel" is NOT verbatim in S209; it is a paraphrase in quotation marks. The source's words are those quoted above.
- Docker on macOS/Windows running inside a Linux VM is in the source and relevant (a Windows or Mac user's "container" is already inside a VM) but is not in the spec.

## Agents now do this themselves (teach the human's part)

- Choosing chat vs task: in merged Claude, "Claude can now figure out what a task needs" and asks if unclear (S102). Teach: you no longer pick the mode; you pick the account, the folder you connect and the approval level.
- Approving each step: Auto mode is the built-in starting mode for Claude Code v2.1.283+ in terminal and VS Code ("a classifier reviews most actions in the background and blocks the risky ones instead of asking you", https://code.claude.com/docs/en/how-claude-code-works), and new desktop Code tab sessions start in Auto (Cowork changelog 2026-09-24). The spec's "keep agents asking for approval first" (Mollick) and MIT's "by default, agent harnesses prompt the user" are no longer the default on the coding surfaces: teach that YOU decide whether to leave it on Auto, and that this decision belongs to the lesson on permission modes. **new this year**
- Fixing setup: `/doctor` diagnoses and can fix installation issues; the agent adapts commands to its shell (S206). Teach recognition only.
- Moving work: Desktop can send a local Code session to the cloud from "Open in" (https://code.claude.com/docs/en/claude-code-on-the-web). The human decision is whether that code and its uncommitted files may leave the machine.

## Traps (commonly said, now wrong or incomplete)

- "Cowork always runs in the cloud now." Only new tasks on Pro and Max since 2026-10-06; Team and Enterprise still have local Cowork in a VM, cloud is a beta org toggle (on for Team, off for Enterprise by default).
- "Anthropic's own May 2026 post says Cowork is a local VM, so that's wrong." It is out of date for Pro and Max only; still how local Cowork works on Team/Enterprise. Use S050 as "stale for your plan", not "false".
- "Claude Code asks before every command." Auto mode is now the starting mode for current versions on terminal, VS Code and desktop Code tab.
- "`claude --remote` starts a cloud session." Deprecated alias; the flag is `--cloud`. `--remote-control` is unrelated (local session steered from a browser).
- "Cloud sessions only upload code if there's no GitHub remote." Also when the Claude GitHub App isn't installed on the repo, even with `/web-setup`.
- "Cloud = Anthropic's computer." Also possibly your organisation's self-hosted environment.
- "Disabling network access means nothing leaves the VM." It can still talk to the Anthropic API.
- "Same model on every surface." OpenAI shipped three model releases (09-22, 09-29, 10-08) to Work and Codex, not Chat.
- "Mollick says use GPT-5.6 Sol for high stakes." His model names are already a generation old; cite the principle, not the names.
- "'claude is not recognized' is always PATH." After an update on Windows it can be a missing `claude.exe` with its own fix.
- "Gemini's privacy notice is from June." Updated 2026-10-13.

## Framing check

- Spec's purpose and conclusion hold. Add "on Pro and Max" to every cloud-Cowork claim, and say the tab split is ending (Unified Claude, beta, rolling out; desktop changelog names November 10 for all orgs on third-party deployments). Date the desktop demo on screen.

- "You set the approval mode" in You vs the agent stays right, but the default the viewer will meet is Auto on coding surfaces; point to the permission-modes lesson rather than teaching modes here.
- Lantern-lesson rule holds: every product fact here moved within the last 30 days (Oct 6 cloud default, Oct 8 Unified Claude date, Oct 13 Gemini notice, Sep 24 Auto default). Keep "as of" dates on every card; use 2026-10-14 where re-verified today.
- No credible source says the whole topic is now the agent's job; the human part (account, plan, connected folder, what crosses to the cloud, expert sign-off for work data) is unchanged and becomes more important as mode choice is automated.

## 01 — The point
[[purpose]]In this lesson you'll learn what git's save points, parallel lines and remote copies are, and how to read the trail your agent leaves, so you notice what it touched. [[conclusion]]The agent types every git command, so your part is recognition: know that a save point and a copy elsewhere exist, which branch is live, what the diff changed, and whether it touched anything you never named. [[why]]An agent can save, branch and push in seconds, so a mistake travels in seconds too.

## 04 — Stones: a commit is a save point
[[stone]]Each time the agent commits, the guide sets a stone on the path: a save point, a snapshot of the whole project at that moment. [[parent]]Each stone records the one before it, so you can walk back along the line. [[set]]Stones are set in place: you add new ones; you don't edit old ones. [[ask]]You never type a commit. You say "commit my changes with a descriptive message". [[habit]]People cleaning up after agents give the same advice: commit often, and before any big change. ## 06 — The ranger station: a copy that lives elsewhere
[[station]]Across the valley stands a ranger station. A remote is a copy of the map kept there. [[notgithub]]And git is not GitHub: git is the stones and signposts in your folder; GitHub is one place to keep a copy. [[burn]]In a forum thread this October, an agent's delete took a project's source and its hidden git folder together. [[cloud]]When there's a copy on GitHub, a cloud session clones that copy, not your laptop, so push first; the lesson on where your agent works has the rest. [[breaks]]Here the picture breaks: every git copy is full and equal, and "the original" is just the one everyone agrees on.

## 10 — The noticeboard: pushing is a decision
[[push]]Sending stones to the station is a push, and it's a decision. [[auto]]As of October 2026, Claude Code's auto mode allows pushing to any branch of the repository you're in, the default branch included. [[deploy]]A branch named like a deploy target, such as production, is judged on its own, and the remote's own branch protection still applies. [[board]]A public remote is the station's noticeboard, facing the road, read by anyone passing. [[pixel]]In late September, Glow Labs researchers found coding agents that, unable to attach an image where they were working, put internal screenshots in public GitHub repositories instead. One helper's default creates a public repository. The researchers counted more than thirteen thousand images from over three hundred organisations: their own count, not an independent audit. [[known]]Auto mode blocks pushing secrets or personal data to a repository known to be public. If it can't tell, that alone won't stop a push; files marked sensitive are blocked either way. Whether yours is public is yours to know.
> S052 (read 2026-10-23): "Pushing to any branch of the repository you're working in, including the default branch"; deploy-named branches (`production`, `gh-pages`) "isn't covered"; "The remote's own branch protection still applies." History on the card only: "for about a week in July 2026 (v2.1.203 to v2.1.211) auto mode allowed fewer pushes; advice from then is out of date" (versions: Choose a permission mode; dates: Claude Code changelog). Never "pushes to main were blocked before v2.1.203". Visibility card: "When a repository's visibility isn't established, the classifier doesn't block on that alone; it judges the content against the other rules instead." plus the sensitive-files rule: "the repository being private doesn't clear it". ## 11 — Pencil and torn stones
[[pencil]]A pull request is a proposed stretch of trail, drawn in pencil, waiting to be inked. [[ci]]Claude Code watches its automated checks and can fix failures. [[merge]]Inking it is a switch you flip, the desktop app's Merge when ready, and auto mode blocks merging a pull request no human approved. Who decides: the lesson on who signs off before you ship. [[tear]]Rewriting history tears stones out and re-lays them, so every other copy disagrees. [[names]]Names to recognise in the trail, never to type: force push and amending a pushed commit rewrite history; reset hard, clean and stash drop throw away work not yet saved. Auto mode blocks them by default. [[revert]]Lovable's docs give the safe way: to undo a change, add a commit that reverts it.
> S208 ("monitors CI check results and can automatically fix failures"). Merge when ready (Use Claude Code Desktop reference page, read 2026-10-23): turns on GitHub's auto-merge for that PR when you switch it on; disabled in SSH and WSL sessions. Never "the app merges once checks pass". S052 card: "Merging a pull request no human has approved, approving Claude's own pull request, or disabling CI checks". "Recognise, don't type" list: `git push --force`, `git reset --hard`, `git checkout -- .`, `git restore .`, `git clean -fd`, `git stash drop`, `git stash clear`, amend after push; auto mode runs `git status` itself first (S052). S212 card: "Do not force-push, rebase, or squash commits that are already on the synced branch." · "To undo a change, add a commit that reverts it."; a rewrite replaces Lovable's copy, which the owner can restore from a backup (since 2026-10-05). What counts as evidence: the lesson on checking code you can't read (card chip).

## 12 — The eraser: checkpoints are not git
[[eraser]]Claude Code's rewind, built on checkpoints, is the guide's pencil eraser. [[only]]Anthropic's best-practices page says checkpoints only track changes made through Claude's file editing tools; changes made through Bash commands or external processes are not captured. This isn't a replacement for git. [[remote]]And anything that reached a remote system, like a deployment or a push, can't be rubbed out.

## 13 — You vs the agent
[[agent]]The agent types every git command: commits, branches, conflicts, pushes, pull requests, fixes for failing checks. Asked, it lists the files it changed, says whether a remote exists and is public, and names the default branch. [[you]]You check that a copy elsewhere exists, private or public as you intend; which branch is the default, and which one your host deploys; and the changed files. [[decide]]You decide what merges, and you ask for evidence, not a claim. [[rule]]Saying "don't push" makes auto mode block a push, but that can be lost when the conversation is compacted. For a guarantee, use a deny rule or branch protection: the lesson on rules that actually hold. [[expert]]Bring in an expert when shared history must be rewritten; when a secret or personal data was pushed, since the key must be revoked and rotated first: the lesson on keys; or when you can't tell what a step touched on a machine with real credentials.
> S206, S208, S129 (agent list; "merges" left out on purpose: merging is GitHub's auto-merge, which you switch on). S052 (read 2026-10-23): stated boundaries are a block signal, "can be lost if context compaction removes the message"; "For a hard guarantee, add a deny rule." Never "telling it does nothing", never "it's a hard rule". Expert card adds "deleting the commit does nothing".

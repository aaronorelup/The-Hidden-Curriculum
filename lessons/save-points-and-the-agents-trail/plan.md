### 13 · You vs the agent (55 s, about 130 words) — mandatory, from the spec's "You vs the agent", updated
- **The agent does on its own:** types every git command: commits, branches, merges when told to, resolves conflicts, pushes, opens pull requests, watches CI and fixes failures (S206, S208, S129). Asked, it lists the files it changed, shows whether a remote exists and whether it is public, names the default branch, and annotates its own trail with what each command read, wrote or contacted. In auto mode it may push to any branch of the working repository, the default included, but is blocked by default from force push, discarding uncommitted work, changing remotes you didn't name, pushing secrets or personal data to a known-public repository, and merging a pull request no human approved (S052). (Drop "merges on its own" from the spec's list: merging is GitHub's auto-merge, which you switch on; section 11.)
- **You check and decide:** that a remote exists and is private or public as you intend; which branch is the default and which one your host deploys (S026); what the diff changed, looking for anything you never named (S069, S208); what merges, and whether the agent may push to the live branch at all. Saying "don't push" does make auto mode block a push, but only while that message is still in the conversation; it can be lost when the conversation is compacted, so for a guarantee use a deny rule or the remote's branch protection (S052, read 2026-10-23; enforcement is "the lesson on rules that actually hold"). Ask for evidence rather than a claim (S117).
- **Bring in an expert** when history must be rewritten on a repository other people share; when a secret or personal data was pushed (the key must be revoked and rotated first: "the lesson on keys"; deleting the commit does nothing); or when you cannot tell what an action touched and the machine holds real credentials.

## 6. Mental model: the trail map

- **Opening picture (03):** a hand-drawn trail map. You are the walker who chooses where to go; the agent is the guide who carries the pen and draws on the map for you. You never draw; you read.
- **It transforms:**
  - 04: the guide lays **stones** (save points) along the path, each one numbered and pointing back to the stone before it. Stones are set in place: you add new ones, you don't move old ones.
  - 05: a **side trail** forks off, with a wooden **signpost** carrying a name (`main`, `feature/...`) that slides forward each time a stone is added. One signpost has a lantern on it: the trail visitors are sent down (the live branch). The AO-043 line: a lantern lit on the wrong signpost.
  - 06: a **copy of the map** lodged at the ranger station across the valley (the remote). Only stones you have sent there exist there. Burn the map at home and the station's copy is all you have; no station, no copy.
  - 07: the guide's **footprints** across the map: each print stamped with a verb and an arrow to its target. One print points off the map, at a place you never mentioned.
  - 08: tracing paper laid over yesterday's map: what was added in one colour, what was removed in another, and a list of the squares that changed. One square you never asked about.
  - 10: the ranger station has a **noticeboard** facing the road: a public remote is pinned there for anyone walking past (PixelLeak).
  - 11: a pull request is a proposed new stretch drawn in pencil, waiting for someone to ink it; "rewriting history" is tearing stones out and re-laying them, which makes every other copy of the map disagree.
  - 12: the guide's own pencil eraser (checkpoints): it rubs out what the guide drew with the pen, but not what was done by hand outside the map, and never what was already sent to the station.
- **Where it breaks (say it plainly, 06 and 11):** (1) a real map has one original; every git copy is a full, equal copy, and "the" original is only the one people agree to treat as it; (2) stones can be torn out: git's history can be rewritten (force push), which is exactly why those verbs are blocked by default; (3) a signpost is only a name: moving it moves nothing on the ground, and which signpost carries the lantern is decided by a setting outside the map (the host, the platform), not by git.

Fix the line and the "out-of-date framing" bullet that repeats it.
2. **[CHANGED] S208's desktop quickstart no longer says Claude "can ... merge the PR once all checks pass".** It now reads "monitors CI check results and can automatically fix failures". 3. **[CHANGED] S176's first recovery step was not "check Git remotes".** sattyamjjain's reply (2026-10-04) lists "stop writing to E:" first and checking Git remotes second.
4. **[new 2026] Auto mode now treats boundaries you state in the conversation ("don't push") as a block signal.** This refines the spec's "a prose request is not a control". It is a signal, not a guarantee: the boundary can be lost when the context is compacted, and the docs say to use a deny rule "for a hard guarantee".
5. **[new 2026] A push to a branch whose name marks it as a deploy target is not covered by the push allowance.** For a branch such as `production` or `gh-pages`, auto mode "judges a push there on its own terms". This relates to AO-043 and to the "which branch is live" idea.

### 6. Rewriting history breaks the other copies (brief)
- Lovable: "Do not force-push, rebase, or squash commits that are already on the synced branch." **New:** "When you rewrite its history, the next sync saves a backup of Lovable's copy and then replaces it with yours", and "To undo a change, add a commit that reverts it." https://docs.lovable.dev/integrations/git-sync-overview.md **[new 2026]**
- **[CHANGED, additive]** The auto-mode blocked list is now longer than the spec's: force push; `git reset --hard`, `git checkout -- .`, **`git restore .`**, `git clean -fd`, `git stash drop`, **`git stash clear`**; `git commit --amend` when HEAD **was not created in this session**; from v2.1.198 (2026-07-01) amend when HEAD has already been pushed (a message-only reword of Claude's own commit is allowed). ### 7. Checkpoints are not git (brief)
- Best practices, confirmed verbatim: "Checkpoints only track changes made through Claude's file editing tools. Changes made through Bash commands or external processes are not captured. This isn't a replacement for git." https://code.claude.com/docs/en/best-practices **[established]**
- How Claude Code works, confirmed: "Actions that affect remote systems (databases, APIs, deployments) can't be checkpointed." https://code.claude.com/docs/en/how-claude-code-works **[established]**
- **[new 2026] Detail that affects the demo** (Checkpointing page, read 2026-10-23): "Once Claude has edited a file with its file editing tools in your conversation, `/rewind` undoes changes that Bash commands make to that file afterward. ## Change arc (git and agents)
- **Before agents:** git was a tool you typed by hand. MIT's 2026 lecture still teaches its model because the interface is hard to memorise, and Aaron in May 2025 called git "the worst of it" (S209; S211, published 2026-08-08). **[established]**
- **What changed (2026):** agents type every git command, and Claude Code's auto mode, the starting mode for terminal and VS Code since v2.1.283 (2026-09-25), lets a classifier approve pushes to any branch, the default branch included. It blocks history rewrites, remote changes, unapproved merges and public-repo leaks by default (S052). Incidents through 2026 show the gaps in between: force-push collapse (2026-03-11), pushes of deletions to `main` (Karakun, 2026-08-28), AO-043's side branch going live (2026-10-08), PixelLeak's public screenshot repositories (2026-09-29). **[new 2026]**
- **Now / heading:** the safeguards are moving out of prose and into the platform. The classifier honours stated boundaries but says to use deny rules for a guarantee. The GitHub CLI added `--attach` (2026-09-01), and GitHub added bulk migration of branch protections to rulesets (2026-10-20, https://github.blog/changelog/2026-10-20-bulk-migrate-branch-protections-to-rulesets-for-a-repository/). That points to the human's job becoming *choosing and checking the settings* (default branch, protection, visibility) rather than watching each command. **[speculation for "heading"; the dated items are established]**

## Traps (things commonly said that are now wrong)
- "Before v2.1.203 Claude Code blocked pushes to main": not what the current docs say. The restriction ran v2.1.203 to v2.1.211 (July 7 to 15, 2026). This trap is **in the spec itself**.
- "The desktop app merges your PR once checks pass": it turns on GitHub's auto-merge only when you choose **Merge when ready**, and that is disabled in SSH and WSL sessions (S208/desktop docs, read 2026-10-23).
- "Telling the agent 'don't push' does nothing": in auto mode it now does something (it is a classifier block signal), but it is not durable and can be lost to compaction. "It's a hard rule" is also wrong.
- "Auto mode lets it push anywhere in the repo": not to a branch named like a deploy target (`production`, `gh-pages`), which the classifier judges on its own terms.
- "Rewind will undo the files a shell command deleted": only for files Claude had already edited with its file tool in that conversation. "Rewind never touches shell changes" is also slightly wrong now.
- "If there is no remote, a cloud session can't get my code": `claude --cloud` now bundles and uploads a local repository with no remote, including uncommitted tracked changes. On native Windows that includes uncommitted edits to `.env`-style files. It is still not a backup.
- "Lovable breaks if your main branch is protected": Lovable now pushes to a `lovable-sync` branch instead. Third-party guides (RapidDev, 2026) still say renaming the repository breaks the sync; Lovable's docs now say GitHub and Bitbucket follow renames (GitLab still breaks).
- "Agents need public repos to show screenshots on PRs": since GitHub CLI v2.99.0 (2026-09-01), `--attach` uploads media to the PR itself.
- "A cloud diff shows everything that changed": as of v2.1.309 (2026-10-22) the Changes pane can list only pushed commits or only Claude's edits, and it labels which.

## Framing check (is any of this now the agent's job?)
- **Typing git:** the agent's job, as the spec already says. Keep "recognition, not operation".
- **Reviewing its own diff:** partly the agent's now. The desktop quickstart offers `/code-review` "to have Claude review the changes itself", and best practices recommend a verification subagent. The human's part does not go away: an agent review checks the code for bugs, but only you know which files you never named. Teach the changed-files list as *your* check and mention that the agent can review the code too. Say so in the lesson.
- **Watching CI and fixing failures:** the agent's job (Auto-fix). The human's job is deciding whether to flip **Merge when ready** and whether a PR needs a human approval at all (auto mode blocks merges no human approved).
- **Guarding against dangerous git verbs:** largely the platform's job now (the auto-mode blocked list). The human's job moves to the settings the agent cannot see or should not change: default branch, which branch the host deploys, branch protection, repository visibility. That matches the spec's "You" list, which needs no topic change. The PixelLeak, Karakun and AO-043 cases all happened while agents behaved "correctly by what they could see".
- **No part of the topic is out of date.** The concepts hold; the specific fixes are the default-branch history, the merge wording and the S176 recovery-step order.

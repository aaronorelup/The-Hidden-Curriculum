# S026 — AO-043 (Aaron Orelup)

**Credit:** Aaron Orelup, "AO-043: A cloud session pushed one post from a branch, and my whole site went back to August", aaronorelup.com Ledger, published 2026-10-09 (incident 2026-10-08, Central time). https://aaronorelup.com/ledger/the-branch-that-went-live/
Re-read in full 2026-10-23 (live page, HTTP 200). Kind: Aaron's own practice. Tell it in the third person ("Aaron's site...").

## What this lesson uses, checked against the post

The lesson uses it in four places: one line in C124.2 (a callback; the full story belongs to the lesson on getting from your laptop to a URL), the "verb and target" example in C117.2, `/version.json` as evidence in C117.4, and the "You" checklist (which branch is the default, which one the host deploys).

**The one-line case (C124.2)**
- A cloud Claude Code session (Claude Haiku 5.5, started on claude.ai) pushed a side branch at 00:39 on 8 Oct (commit 2ac796e, 05:39:08 UTC). Cloudflare built it and deployed it to production "about forty seconds later": the timeline gives 00:39:08 for the commit and push, and 00:39:48 for the build and deploy with `wrangler deploy`.
- The live site became the site "as it stood on 2 August": four posts, and none of the thirty-nine posts written since.
- Rollback at 00:47:58 (`npx wrangler rollback 34b650ef… --name blog`). The post states: "The site had been wrong for 8 minutes 10 seconds." The lede rounds this to "eight minutes".
- The branch was `claude/pensive-hamilton-yuqj1a`. It was a side branch: not main, and not the default branch.

**Why it got through: "Three settings in a row"**
1. The default branch. GitHub still listed `master` as the default branch. `master` had been frozen at AO-003 since 2 August, while all the work happened on `main`. Laptop sessions never noticed because the local checkout was on main.
2. What a cloud session gets. Per the post, a claude.ai cloud session "starts with a fresh clone of the repository, on the default branch, and nothing else". The blog's rules lived in an uncommitted CLAUDE.md one folder above the repo, so the cloud session never saw them. It found three posts and numbered its own post AO-004.
3. What Cloudflare did with a branch. In Workers Builds, "Builds for non-production branches" was switched on, and the command those builds ran was `npx wrangler deploy`, which replaces the live site. So any pushed branch went to production, not to a preview.
- Aaron's verdict on the agent: "The session did nothing wrong by what it could see." (quote 1 of 2)

**The diff as a trail (useful for C117)**
- The commit's stat shows exactly two files: `public/paintings/scythe.png` (binary, 0 -> 3,319,429 bytes) and `src/content/posts/scythe-and-serpent.md` (+17 lines). The post calls it "Two files on top of August". The change itself was small; the damage came from the old branch it was built on, not from the files it touched.

**The fixes: the post's "four separate stops"**
1. GitHub's default branch is now `main`.
2. `master` is gone. It was deleted along with the Haiku branch, and the agent noted the commits each could be restored from.
3. Cloudflare only builds main. Branch builds were turned off, and their command was changed to `npx wrangler versions upload` ("uploads a version, never deploys") as a backup, in case branch builds are ever switched back on.
4. A build guard. The build throws an error when `WORKERS_CI_BRANCH` is anything other than `main`. It was tested both ways before it was pushed. The agent stated its limit: old branches that do not contain the guard would still deploy.
- Also done, but not counted among the four stops: a short CLAUDE.md committed into the repo (e537351) for sessions that only ever see the repo.

**What the agent did and what needed Aaron (You vs the agent)**
- The laptop session (Opus 5.5) did the following in its first turn, 16 minutes in all: the diagnosis, the rollback, the live checks (five pages and a 206 byte-range response), the default-branch switch, the build guard and the CLAUDE.md. At 00:58 it asked before doing two things: changing the Cloudflare setting in Aaron's Chrome, and deleting the two old branches.
- Aaron approved both at 16:08. Chrome was signed out of Cloudflare, so the agent stopped, because typing the password was Aaron's job. He signed in at 16:28, and the setting was changed at 16:30.
- A side detail: Cloudflare's deploy history did not show which deploys came from a branch ("Nothing marks one as a branch"). The pairs of commit and deployed version had to be read from Cloudflare's check runs.

**`/version.json` as evidence (C117.4)**
- Added afterwards: "Every build writes /version.json with the commit, the branch Cloudflare built, the time, and the newest listed post." The repo's instructions tell every session to compare it with what it just pushed.
- Live check on 2026-10-23: https://aaronorelup.com/version.json returns `commit`, `branch: "main"`, `built`, `posts` (a post count, which the post does not mention) and `newest`.
- Before this, the only alarm was Aaron happening to look at the site at 00:42, three minutes after it broke. Short form: there was "nowhere to ask the live site which commit it was built from" (quote 2 of 2).

## What the spec says that the source does NOT say (or says differently)

1. **C117.2 cites S026 for "a push to the default branch".** This is wrong. AO-043 was a push to a **side** branch (`claude/pensive-hamilton-yuqj1a`) that went live because the host deployed every branch. The session **started from** the stale default branch; it did not push to it. The verb-and-target example from S026 should be "a push to a branch the host deploys" or "a push whose branch went live". Keep S052 alone for "a push to the default branch".
2. **"The four fixes" (the spec's source line).** The post counts four *stops*: the default branch is main, master is deleted, Cloudflare builds only main, and the build guard. The committed CLAUDE.md and `/version.json` are extra measures, not part of the four. If the lesson lists "four fixes", these are the four.
3. **"Built and put into production about forty seconds later"** is correct (00:39:08 to 00:39:48). **"Went back to August for 8 minutes 10 seconds"** is correct, measured to the 00:47:58 rollback. The lede says "eight minutes"; use the exact figure.
4. **"Which branch is live is a setting somebody chose"** is a fair reading, but the post stresses that nobody had looked at it in weeks: "Three settings that nobody had looked at since August". The point is that the settings were *stale*, not that someone recently chose them.
5. **The post says a claude.ai cloud session clones "on the default branch".** That is Aaron's observation for a session started in the browser. S129 (current docs) describes `claude --cloud` from a terminal, which clones "at your current branch". These are different ways of starting a session and do not contradict each other. Do not merge them into one rule.
6. **The post does not mention GitHub branch protection, Lovable or Claude Code's auto-mode push rules.** Those claims need their own sources (S052, S212).

## Currency (checked 2026-10-23)

- **No correction or follow-up.** The Ledger index (AO-044 to AO-064, the latest dated 2026-10-23) has no later post revisiting AO-043. The page is unchanged, and `/version.json` is live and reports `main`.
- **Cloudflare's terms have moved on.** The current Workers Builds docs still describe "Builds for non-production branches". They say its deploy command **defaults to `npx wrangler versions upload`**, so Aaron's `wrangler deploy` was a setting someone had changed, not the default. Cloudflare's build-branches page (updated 2026-10-01) now also describes the newer **Worker Previews** (`npx wrangler preview`, launched September 2026). So do not present Aaron's Cloudflare settings screen as what a new project sees today. Teach the idea instead: which branch your host deploys is a setting, and you check it.

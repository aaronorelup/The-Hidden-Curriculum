# S208: Get started with the desktop app (Claude Code docs)

**Credit:** Anthropic, "Get started with the desktop app", Claude Code documentation (code.claude.com). Undated live docs page. First read 2026-10-12 (sources.md); re-read in full 2026-10-23 (Markdown version at https://code.claude.com/docs/en/desktop-quickstart.md; server date Fri, 23 Oct 2026). URL: https://code.claude.com/docs/en/desktop-quickstart

**What it is:** Anthropic's quickstart for the Code tab of the Claude desktop app (macOS, Windows, Linux beta). It covers install, picking an environment and a folder, a model, a first prompt, reviewing changes, and a "Now what?" list of features. It is a how-to page, not a study: it has no measurements. Its only number-like item is the example indicator `+12 -1`. The detail behind several of its lines lives on the linked reference page "Use Claude Code Desktop" (https://code.claude.com/docs/en/desktop), quoted below where it matters and labelled as such.

## What this lesson uses from it (checked against the page, 2026-10-23)

### C124.3: what changed, the diff and the list of changed files (teach)
- Verbatim, under the bold lead **"Review changes before committing."**: "After Claude edits files, a `+12 -1` indicator appears. Click it to open the diff view, review modifications file by file, and comment on specific lines. Claude reads your comments and revises." The spec's quote matches the page word for word.
- The same paragraph now continues: "To have Claude review the changes itself, enter `/code-review` in the prompt box." (This was already on the 2026-10-17 archived copy.)
- `+12 -1` is an **example** ("an indicator such as `+12 -1`"), not a fixed value. The page never defines the two numbers. Reading them as lines added and lines removed is the lesson's gloss. The reference page calls them "the line counts, such as `+12 -1`", shown in the **Changes** card of the session details panel; clicking them, or **Changes** in the session's title bar, opens the diff view (desktop reference, "Review changes with diff view").
- When the indicator appears depends on the permission mode (step 4, "Review and accept changes"). In **Auto or Accept edits**, "Claude applies its file changes, and an indicator such as `+12 -1` appears". In **Manual**, Claude proposes each change and waits, and you see "A diff showing exactly what will change" with buttons to approve or decline each change. So in Auto and Accept edits the diff is reviewed **after** the edit is already on disk.
- Permission modes as the page lists them: Auto ("a classifier reviews actions in the background and blocks the risky ones instead of asking you"), Manual (asks before editing files or running commands), Accept edits (auto-accepts file edits), Plan (proposes an approach without editing any files).
- The reference page says the diff view is for reviewing "file by file before creating a pull request", and that line comments come back "as a new diff you can review".

### C124.5 / C117: a pull request is a proposed change you review (brief)
- **Current wording (2026-10-23), verbatim:** "**Track your pull request.** After opening a PR, Claude Code monitors CI check results and can automatically fix failures. See Monitor pull request status."
- **The spec's quote is no longer on the page.** The spec quotes "...can automatically fix failures or merge the PR once all checks pass". That clause was on the page on 2026-10-12 and on the Wayback copy of 2026-10-17 (web.archive.org/web/20261017040845/...), and has been removed since. Today S208 says nothing about merging.
- What the linked reference page says now (desktop reference, "Monitor pull request status"; this is not S208 itself): "To have Claude fix failing checks, or to have GitHub merge the pull request, turn on **Auto-fix** or **Merge when ready**." Both are switched on per pull request from the **⋮** menu beside the PR in the Changes card. **Merge when ready** "turns on GitHub's auto-merge for the PR". In a local session Desktop requests a squash merge unless the base branch uses a merge queue. It is disabled in SSH and WSL sessions, and does not turn on if the repository doesn't allow auto-merge. **Auto-fix** in a local session also addresses new review comments from the repository owner, an organisation member, a collaborator or a GitHub App.
- So the accurate framing as of 2026-10-23: the agent watches CI and fixes failures; merging is GitHub's auto-merge, which **you** switch on per PR. GitHub then merges after the checks and the branch rules pass. Neither page says Claude merges by its own decision.
- Related, on the reference page (archive section): "commit the ones you want to keep before a pull request that Claude opened in the session merges", because when only untracked files are left, Desktop "can then delete them without asking". This is a real "what will surprise you" point, but it is the reference page, not S208.

### C117 "You vs the agent": the agent types the git; the desktop app hides the terminal, not the effects
- The page's own framing: "You can ask Claude to work on the code in a folder on your computer and review its changes without using a terminal." This supports "the agent types every git command" and the framing to avoid, "The desktop app means I don't need any of this". The page still sends you to review changes. Note that "It hides the terminal, not the effects" is the spec's wording, not the page's.
- A terminal is still there: "Open the terminal with **Ctrl+`** to run commands alongside your session". You can drag the chat, diff, terminal, file and browser panes into any layout.
- Every session starts with an environment and a folder. The page names the **Local** group, plus **Cloud** ("sessions in the cloud that continue even if you close the app"), **SSH** and **WSL** (Windows: "Claude Code, tools, and git execute on the Linux side with native paths"). It also says "Each session tracks its own context and changes". The lesson on where the agent works owns this.
- Parallel sessions can run "optionally each in its own Git worktree" (one line, if needed. The page does not explain worktrees).

### Minor facts on the page (only if needed, dated 2026-10-23)
- Requires a Pro, Max, Team or Enterprise subscription. The desktop app includes Claude Code, so no Node.js or CLI install is needed for the Code tab.
- Downloads: macOS universal, Windows x64 and ARM64, Linux (beta) via apt or .deb for Ubuntu and Debian.
- When the dev server runs, the app opens in the Browser pane. Other features listed: scheduled tasks, side chat, moving a session to the cloud.

## What the spec attributes to S208 that S208 does not (or no longer) say
- **C124.5's quote is out of date.** "...or merge the PR once all checks pass" was removed from the page between 2026-10-17 and 2026-10-23. Use the current sentence. For merging, cite the desktop reference page ("Merge when ready" turns on GitHub's auto-merge, which you switch on per PR), or drop the merge half.
- The sources.md and spec summary "PR monitoring that can fix and merge" (spec line 65, sources.md "Contributes") needs the same fix: the page now says monitor and fix only.
- That `+12 -1` means lines added and lines removed: the page shows it only as an example and never defines it. This is a safe gloss, but it is the lesson's.
- "It hides the terminal, not the effects" (framings to avoid): the spec's wording. The page supports it but does not say it.
- Nothing on S208 is about remotes, push, branches, default branches, branch protection, force push, or what auto mode blocks (those are S052, S129 and others). Nothing about spotting a file you never asked about (S069). S208 offers only the file-by-file diff that makes such a check possible.
- The spec's "You vs the agent" line credits S208 for "opens pull requests, watches CI and fixes failures". The watch-and-fix part is on the page. That the agent **opens** the PR is implied ("After opening a PR"), not stated.
- sources.md's "Contributes" also lists "dev servers in the Browser pane; PRs and CI". Both are still on the page; not used by this lesson beyond C124.5.

## Currency check (2026-10-23)
- Live page re-fetched today. The `+12 -1` indicator and diff-view sentence, the "Review changes before committing" lead, the four permission modes and the four environments are unchanged from the 2026-10-12 and 2026-10-17 copies (Wayback snapshots 20261012210617 and 20261017040845, compared directly).
- **Changed:** the PR line lost its auto-merge clause (see above). Merging is now described on the reference page as an opt-in **Merge when ready** switch that hands the merge to GitHub's auto-merge, plus **Auto-fix**, which can now also answer other people's review comments. A web search found no announcement of the wording change. Anthropic's February 2026 article "Bringing automated preview, review, and merge to Claude Code on desktop" (claude.com/resources/articles/preview-review-and-merge-with-claude-code) describes the older "Claude attempts to merge once checks pass" framing and should not be used as current.
- Topic currency: watching CI and fixing failures is now the agent's job, done by itself. The human's part, which the lesson should teach, is reading the diff and the changed-file list before anything merges, and deciding whether to switch on Merge when ready for a given PR. That fits the spec's "You decide what merges".

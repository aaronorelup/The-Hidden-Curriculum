## 03 — The mental model
[[mental-model]]Picture a map drawn on the disk. Its edge is the root, where every address begins. On Windows, each drive has its own root, so there is one edge per drive. Now picture giving directions on that map: three streets east, then two up. Those directions only work from one spot. [[you-are-here]]So put a you-are-here dot on the map. [[dot-is-working-dir]]That dot is the working directory. Every running program has one. Keep this picture. The map is going to get a second dot.

## 04 — Absolute paths: the full address
[[absolute]]An absolute path is a full street address. It starts at the root of the disk, the edge of the map, and counts from there. So it reads the same wherever the dot happens to be. [[windows-form]]On Windows, the root begins with a drive letter, so you'll see C colon backslash, then folder names, then the file. [[unix-form]]On macOS and Linux, the root is a single forward slash. Microsoft's own wording is that a full path starts from a drive or a root. [[separators]]The backslash is the Windows habit, and the forward slash is the Unix habit. Windows generally accepts forward slashes too, and so does PowerShell. The separator is a naming convention. The operating system decides what the name means.
> Concept only. Screen: one path string, parts lit in turn (drive, folders, file), with C:\ and / shown literally.

## 05 — Relative paths and the working directory
[[relative]]A relative path leaves out the start. It says three streets from here, and here means the working directory. [[inherit]]Every running program has a working directory. It is set when the program starts, and it is inherited from whatever started it. If you typed the command, the place you typed it became the dot. [[measured-from]]A relative path is measured from that directory. Not from the file that contains it, and not from the root of the disk. [[prompt-dot]]Many terminals show the dot in the prompt. PowerShell's default prompt looks like P S C colon backslash, then your folder, then a greater-than sign. That prompt is the dot, printed on the screen for you. Read it before you trust any relative name.
> Prompt text is an example. Show the literal prompt, PS C:\Users\you\project>, on screen.

## 06 — The same name, two places
[[works-on-my-machine]]Here is where "it works on my machine" comes from. Imagine a script that opens a file called data dot see S V, by its bare name. [[two-places]]Run it from the project folder, and the name finds the file. The script works. Run it from another folder, and the same name looks in that folder, finds nothing, and fails. [[same-name]]The code did not change. The dot moved. Your friend's dot sits on their own project, so for them it works. Both of you are right about your own dot. When a relative name fails, check where the program was standing before you check the file.
> Words only, no code block. Both panels show the same script file, unchanged.

## 07 — Shortcuts, and where the picture breaks
[[tilde]]Three shortcuts show up in paths. Tilde means your home folder, and the shell expands it for you. On Windows, that is usually something like C colon backslash Users and your name. [[dots]]A single dot means this folder. Two dots mean the folder one step up. You only need to recognize them for now. [[break-copy]]Now the place where the picture breaks. Real people carry their own dot. A computer's dot is a stored value inside each running program. When one program starts another, the child gets a copy, not a shared pointer. So there are many copies, one per running program. [[root-end]]And the top of the disk has nowhere further to go. Two dots at the root stay at the root. Don't stretch the metaphor past that edge.

## 08 — What is really going on
[[cd-scope]]So what does a C D actually do? It changes the dot for the session that ran it, and only that session. [[child-process]]A child process cannot move its parent. If a program changes its own folder, the window you typed into keeps its own dot. That is the general rule, for every program that keeps a working directory. [[python-second]]Python is the clearest case of a second list. Other tools have their own lookups too. Node, for example, resolves a required file from the calling file's folder, not the shell's. When you run python script dot P Y, the import list starts with that script's folder. With dash M or dash C, it starts with the current folder. Python 3.11 added dash P and an environment variable, P Y T H O N safe path, which stop Python putting those folders first. That story belongs to 05.02. A file path and an import path are two different lookups.

## 09 — The surprises you'll hit
[[err-no-such-file]]On macOS, on Linux, and in Git Bash, you'll often see: no such file or directory. Read it as: this name is not found from this dot. [[err-python]]Python is more specific. You'll see a line like: FileNotFoundError, then bracketed err-no two, then no such file or directory, then the name in quotes, data dot see S V. The name is right. The place is wrong. [[err-powershell]]PowerShell usually says something like: cannot find path, because it does not exist. Check the exact words on your own screen, because they change with the command. [[git-bash-spelling]]In Git Bash, C colon backslash Users shows up as slash C slash Users. Same place, another spelling. [[agent-reset]]If you use Claude Code, a tool result may end with: Shell C W D was reset to, and then a folder. Some people report seeing that after a C D left the project, and the shell went back to the project folder.

## 10 — The lantern: agents and the folder they stand in
[[lantern-change]]Five years ago, in 2021, no mainstream coding agent ran commands for you. The person at the keyboard typed every C D, and only that person moved the dot. Claude Code opened as a limited research preview in the terminal in February 2025. Codex C L I followed in April 2025. Now a coding agent runs commands from a working directory it inherited, and it types the C D itself. [[lantern-rule]]Claude Code's shell keeps its folder from one command to the next. Users have reported that a C D out of the project, or out of an added directory, gets pulled back to the project folder, and the result says so. Subagents don't carry a C D over. [[lantern-sandbox]]The sandbox runs on macOS, Linux, and Windows Subsystem for Linux version two, per the docs read this month. Native Windows runs commands without that sandbox, so on Windows, the folder rule is the one that matters. [[lantern-reported]]Some people have reported the folder resetting between every command. That is a reported issue, not a rule. [[lantern-worktree]]A worktree is a second folder for the same project, on its own branch, sharing one history. The detail is 08.11. [[lantern-close]]Agents can resolve paths for you when they know the folder. You still need to know which folder they're standing in, and whether it's the project you think. Where this goes next is a guess. Agents will probably do more of the typing, and the question will still be the same.

## 11 — Safe to ignore for now
You can skip these for now. [[ignore-260]]Windows paths have a 260-character default. Apps have to opt in before that limit lifts, and it takes both a system setting and the app's own manifest. That's module one, lesson eight. [[ignore-slashes]]Forward slashes mostly work on Windows, so you don't need to fight them. [[ignore-wsl]]W S L reaches your C drive under slash mount slash C. [[ignore-python]]Python's dash P option and P Y T H O N safe path are module five, lesson two's story. You don't need to memorize any of this today.

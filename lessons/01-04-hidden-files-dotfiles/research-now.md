# research-now: Hidden files & dotfiles (as of 2026-10-09)

Lens: the invisible config layer as a learner meets it THIS month. Status tags: established / new this year (roughly Oct 2025 to Oct 2026) / beta or announced / speculation / unsourced.
Orchestrator names checked: `.git`, `.env`, `.venv`, `AppData`, `~/.config`, `.claude/`, `CLAUDE.md`, `.cursor`, "MCP configs" are all real, current names; "MCP configs" means several different files per tool (see section 7).

## 1. Why Unix hides dotfiles (the convention's origin)

- The "hidden dotfile" began as a shortcut: `ls` was changed to skip `.` and `..`, and the test simply skipped any name starting with a period; that accidentally hid every dot-named file, and people then started putting config files in home directories as dotfiles. Rob Pike called it an unintended consequence and "a mistake". Status: established (history). Source: Rob Pike, "A lesson in shortcuts", Google+ 2012-08-03, archived copy at https://tookmund.com/2022/03/rob-pike-shortcuts (repost dated 2022-03); summary at https://linux-audit.com/linux-history-how-dot-files-became-hidden-files/ (undated).
- A TUHS mailing-list recollection gives a slightly different version (intent was to hide `.` and `..`; the accidental broad hiding spread via Berkeley). Treat details as folklore-grade; the core "accident, then convention" story is consistent. Status: established (core), details disputed. Source: https://minnie.tuhs.org/mailman3/hyperkitty/list/tuhs@tuhs.org/message/K4IKG3POEGXCESOCL4SMLOR7RRCZDKHW (2019-04).
- Key mental-model point: on Unix/macOS "hidden" is ONLY a naming convention. Nothing is protected or encrypted; `ls -a` or one keystroke shows it. Status: established. Same sources.
- macOS Finder: Shift+Command+. (period) toggles hidden files in Finder; dot-named files like `.git`, `.config` are hidden by default. Status: established. Source: https://velvetshark.com/til/macos-keyboard-shortcut-show-hidden-files (undated); https://www.slashgear.com/1358116/how-to-find-show-hidden-files-mac/ (undated).
- macOS also has a separate "hidden" file flag (chflags) used for e.g. `~/Library`. Status: unsourced in this pass (general knowledge; verify before scripting).

## 2. `~/.config` and the XDG Base Directory spec

- XDG Base Directory Specification is still at version 0.8 (published 2021-05-08); no newer version found. Status: established. Source: https://specifications.freedesktop.org/basedir/latest/ (v0.8, 2021-05-08).
- `$XDG_CONFIG_HOME` defaults to `$HOME/.config` (user config); `$XDG_DATA_HOME` to `$HOME/.local/share`; `$XDG_STATE_HOME` to `$HOME/.local/state` (logs, history, recently used); `$XDG_CACHE_HOME` to `$HOME/.cache`. Paths must be absolute or are ignored. Status: established. Same source.
- Why it matters: it is the "tidy" answer to Pike's complaint (one `.config` folder instead of 100 dotfiles in home). Many tools follow it, many don't; a learner's home folder is a mix of both. Status: established (pattern). Source: https://alchemists.io/articles/xdg_base_directory_specification (2024).
- Real-world current example: Claude Code writes its global git-ignore entry to `$XDG_CONFIG_HOME/git/ignore`, or `~/.config/git/ignore` when unset, i.e. AI tools now write INTO this layer too. Status: new this year (current docs). Source: https://code.claude.com/docs/en/settings (fetched 2026-10-09; page undated).

## 3. Windows: the Hidden attribute and AppData

- Windows has NO dot convention: hiding is a file-system attribute (Hidden, plus "protected operating system files"/System). A file named `.env` is NOT hidden on Windows unless something sets the attribute. Status: established. Source: Git for Windows `core.hideDotFiles` commit message ("On Windows, no such convention exists. Instead, there is an explicit flag"), https://git.lorimer.id.au/gitweb.git/diff/f30afdabbfb9feeec402d351935879caf8b298ad (Git for Windows source, 2016-era).
- Git for Windows sets the Hidden attribute on `.git/` only, by default (`core.hideDotFiles = dotGitOnly`); other dotfiles like `.gitignore` stay visible. Introduced because early unhidden `.git` folders caused confusion and data loss. Status: established. Source: same commit; https://opensource.apple.com/source/Git/Git-128/src/git/Documentation/config/core.txt.auto.html.
- Observed on Aaron's own Windows 11 machine (2026-10-09, `Get-ChildItem -Force`): 46 dot-named items in `C:\Users\soulo` (e.g. `.claude`, `.claude.json`, `.codex`, `.copilot`, `.agents`, `.ssh`, `.gitconfig`, `.npmrc`, `.config`, `.local`, `.cache`, `.vscode`, `.ollama`), and `.claude`, `.ssh`, `.codex` carry NO Hidden attribute. So cross-platform dev and AI tools put Unix-style dotfolders into Windows home folders anyway; on Windows they are "hidden by name only to Unix eyes". Status: established (direct observation, this machine).
- `AppData` sits in the root of each profile (`C:\Users\<name>\AppData`) and is hidden by default; three subfolders: Roaming (follows a domain user between machines; `%APPDATA%`, FOLDERID_RoamingAppData), Local (machine-specific; `%LOCALAPPDATA%`), LocalLow (low-integrity processes such as browser sandboxes). Status: established. Sources: https://learn.microsoft.com/en/windows/win32/shell/csidl (Microsoft Learn, legacy CSIDL page); https://wiert.me/2022/03/02/windows-applications-storing-your-data-in-the-correct-place-roaming-local-locallow-not-documents/ (2022-03-02); https://petri.com/appdata-folder/ (undated, says hidden by default in Win10/11).
- Real examples from Aaron's `AppData\Roaming` (2026-10-09): `Claude` (Claude Desktop, where `claude_desktop_config.json` MCP config lives), `Code` (VS Code), `GitHub CLI`, `Python`, `Notion`, `Bitwarden`, plus game saves. Status: established (direct observation).
- Showing hidden items, current Microsoft wording: Windows 11 File Explorer > View > Show > Hidden items. Windows 10 path differs (Folder Options). Windows 10 support ended 2025-10-14. Status: established. Source: https://support.microsoft.com/en-us/windows/view-hidden-files-and-folders-in-windows-97fbc472-c603-9d90-91d0-1166d1d9f4b5 (fetched 2026-10-09, (c) 2026).
- Settings app: Microsoft announced at Build 2025 (May 2025) that a new Settings > System > Advanced page replaces "For developers" and includes a File Explorer section with "Show hidden and system files", "show file extensions" and "full path in title bar" toggles. Initially Insider-only; whether every consumer build now shows "Advanced" was not confirmed. Status: new this year / rolling out (hedge the label). Sources: https://www.bleepingcomputer.com/news/microsoft/microsoft-confirms-new-advanced-settings-for-windows-11 (2025-05); https://pureinfotech.com/enable-new-advanced-settings-windows-11/ (2025-05).
- File extensions are also hidden by default in Explorer, which is how `notes.txt.py`-style confusions happen. Status: established (default); the BleepingComputer source above lists the "show file extensions" toggle.

## 4. `.git` (the project's history lives in a hidden folder)

- A repo's entire history and config live inside the hidden `.git/` folder at the project root; delete it and the folder is just files again. Status: established. Source: git core.hideDotFiles docs above (rationale: "users have no need to open .git/").
- `.gitignore` tells git which untracked files to never add; it does NOT untrack a file that was already committed (that file stays in history). Status: established. Source: https://git-scm.com/docs/gitignore (current git docs; not re-fetched this pass).
- Python 3.13+ `python -m venv` writes a `.gitignore` containing `*` inside the new environment folder by default (opt out with `--without-scm-ignore-files`), so a fresh `.venv` ignores itself. Status: established (Python 3.13, Oct 2024). Source: https://docs.python.org/3.13/library/venv.html; https://www.pythonmorsels.com/python-313-whats-new/ (2024).
- Agents treat `.git` internals as sensitive: Claude Code's sandbox denies writes to `.git/hooks` and `.git/config` in the working directory; Codex protects `.git` (and `.codex`, `.agents`) as read-only inside writable roots. Status: new this year (current docs). Sources: https://code.claude.com/docs/en/sandboxing (fetched 2026-10-09); https://learn.chatgpt.com/docs/agent-approvals-security (via 01.03 research-now, 2026-10-08).

## 5. `.env` (secrets as plain text in a hidden file)

- Convention: `KEY=value` lines in a file named `.env` at the project root, loaded into environment variables at start. Status: established.
- Node.js now reads `.env` natively: `node --env-file=.env` (added v20.6, experimental) and `process.loadEnvFile()`; both marked stable in v24.10.0 and v22.21.0. Real environment variables win over the file; no `${VAR}` expansion. Status: new this year (stable status). Sources: https://beta.docs.nodejs.org/process/loadEnvFile (Node docs beta site, fetched via search 2026-10); https://env.dev/guides/nodejs-env-variables (undated). Hedge: version numbers come from docs mirror + secondary.
- Python: still a library (python-dotenv), not built in. Status: established. Source: 1Password docs library list below.
- Scale of the leak problem: GitGuardian State of Secrets Sprawl 2026 (5th edition): 28.65M new hardcoded secrets added to public GitHub in 2025 (+34% YoY); AI-service secrets 1,275,105 (+81%); 24,008 unique secrets found in MCP configuration files (2,117 valid); commits co-authored with Claude Code showed a 3.2% secret-leak rate vs 1.5% baseline; internal repos ~6x as likely as public to hold secrets; 64% of valid secrets from 2022 still not revoked. Status: new this year (vendor report; vendor's own numbers). Sources: https://dev.to/gitguardian/the-state-of-secrets-sprawl-2026-ai-service-leaks-surge-81-and-29m-secrets-hit-public-github-2bgj (GitGuardian, 2026); https://thehackernews.com/2026/03/the-state-of-secrets-sprawl-2026-9.html (2026-03).
- GitHub secret scanning push protection has been ON by default for pushes to public repos since late Feb/Mar 2024 (blocks the push when it recognises a supported secret; users can bypass). GitHub had found >1M leaked secrets in public repos in the first 8 weeks of 2024. Status: established. Source: https://github.blog/news-insights/product-news/keeping-secrets-out-of-public-repositories/ (2024-02-29); https://www.helpnetsecurity.com/2024/03/04/github-push-protection/ (2024-03-04).
- Pasted secrets persist: Claude Code transcripts are not encrypted at rest; "If a tool reads a `.env` file or a command prints a credential, that value is written to `projects/<project>/<session>.jsonl`" under `~/.claude`. So reading `.env` into an AI chat copies the secret into ANOTHER hidden folder. Status: established (current docs). Source: https://code.claude.com/docs/en/claude-directory (fetched 2026-10-09).
- Where it is heading (moving secrets out of plain `.env`):
  - 1Password Environments: "Local .env file" destination that mounts a `.env` as a UNIX named pipe; secrets are never on disk, git won't commit a pipe, each read prompts for approval. Mac and Linux only; public beta since 2025-10-29. Status: beta. Sources: https://developer.1password.com/docs/environments/local-env-file (undated docs); https://1password.com/blog/1password-environments-env-files-public-beta (2025-10-29).
  - dotenvx: encrypts each value in `.env` with a public key so the encrypted file can be committed; the private key lives in `.env.keys` (gitignored) or CI secrets. Status: established tool, niche adoption. Sources: https://dotenvx.com (undated); https://www.deployhq.com/guides/dotenvx (updated 2026-08-05).

## 6. `.venv` (a whole Python install hiding in your project)

- `uv venv` (and `uv run` / `uv sync` in a project) creates `.venv` in the project folder by default; no activation needed with uv; `UV_PROJECT_ENVIRONMENT` changes the location. Status: established. Sources: https://mintlify.com/astral-sh/uv/cli/venv (uv CLI reference mirror); https://tds.s-anand.net/2026-02/docs/week-1/02-uv-1-basics/ (2026-02). Verify wording on docs.astral.sh before quoting.
- Python 3.13+ venv auto-ignores itself in git (see section 4). Status: established.

## 8. Hidden config files became an attack surface (2025-2026)

- Rules File Backdoor (Pillar Security, disclosed 2025-03): invisible Unicode instructions hidden in Cursor / Copilot rules files steer the AI into writing malicious code; Cursor said user responsibility; GitHub added a warning for hidden Unicode in files on github.com. Status: established (2025). Sources: https://thehackernews.com/2025/03/new-rules-file-backdoor-attack-lets.html (2025-03); https://securityaffairs.com/175593/hacking/rules-file-backdoor-ai-code-editors-silent-supply-chain-attacks.html (2025-03).
- Cursor CurXecute CVE-2025-54135 (prompt injection makes agent write `.cursor/mcp.json`, which then executes; fixed in 1.3, 2025-07-29) and MCPoison CVE-2025-54136 (an approved `mcp.json` could later be swapped for a malicious one without re-prompt; Check Point, published 2025-08-05). Status: established (2025). Sources: https://blog.checkpoint.com/research/cursor-ide-persistent-code-execution-via-mcp-trust-bypass/ (2025-08-05); https://www.tenable.com/blog/faq-cve-2025-54135-cve-2025-54136-vulnerabilities-in-cursor-curxecute-mcpoison (2025-08).
- Claude Code project-file flaws (Check Point Research, "Caught in the Hook", published 2026-02-25): (1) hooks in a repo's `.claude/settings.json` ran on open (fixed 2025-08-26, GHSA-ph6w-f82w-28w6); (2) `.mcp.json` servers pre-approved via `enableAllProjectMcpServers` / `enabledMcpjsonServers` ran before the trust dialog (CVE-2025-59536, fixed 2025-09-22); (3) `ANTHROPIC_BASE_URL` set in project settings sent the API key to an attacker before trust (CVE-2026-21852, fixed 2025-12-28; tracker lists fix in 2.0.65). Takeaway in the post: project config files "are no longer passive metadata"; review `.claude/` changes like code. Status: new this year (disclosed 2026-02). Sources: https://research.checkpoint.com/2026/rce-and-api-token-exfiltration-through-claude-code-project-files-cve-2025-59536/ (2026-02-25); https://www.theregister.com/2026/02/26/clade_code_cves/ (2026-02-26); https://isitpatched.com/claude-code.
- s1ngularity / Nx (2025-08-26): malicious npm versions of Nx ran a postinstall script that invoked the victim's own AI CLIs (Claude, Gemini, Q) with permission-bypass flags (`--dangerously-skip-permissions`, `--yolo`, `--trust-all-tools`) to search the disk for secrets and wallets, and targeted AI-CLI config/auth files; stolen data posted to public repos named `s1ngularity-repository`. Counts vary (one report: 2,180 accounts, 7,200 repos). Status: established (2025). Sources: https://wiz.io/blog/s1ngularity-supply-chain-attack (2025-08); https://bleepingcomputer.com/news/security/ai-powered-malware-hit-2-180-github-accounts-in-s1ngularity-attack (2025-08/09).
- Shai-Hulud worms (2025-09, and "2.0" 2025-11-21..24): npm worm running TruffleHog to sweep developer machines and CI for tokens, cloud keys and environment variables; Wiz estimate >25,000 developers' secrets exposed in 3 days for 2.0. GitGuardian later counted 294,842 secret occurrences across 6,943 compromised machines in the Shai-Hulud 2 dataset. Status: established (2025). Sources: https://cycode.com/blog/shai-hulud-2-0-deep-dive-and-actionable-steps-you-should-take/ (2025-11); https://www.theregister.com/2025/11/28/posthog_shaihulud/ (2025-11-28); GitGuardian 2026 report link in section 5.
- Lesson-relevant pattern: attackers (and malware) go straight for the hidden layer: `.env`, `.npmrc`, `~/.ssh`, `~/.aws`, AI tool configs and MCP configs. Status: established (synthesis of above).

## 9. Where it is heading (labelled)

- Agents getting explicit "don't touch config" protections (Claude Code protected paths, Codex read-only `.git`/`.codex`): beta-to-established, current docs. Status: new this year.
- Instruction files converging on `AGENTS.md` under the Linux Foundation; tools reading each other's files (Copilot reads CLAUDE.md/GEMINI.md; Claude Code reads AGENTS.md). Status: new this year; full convergence is speculation.
- Secrets leaving plain-text `.env` (named-pipe mounts, encrypted `.env`, secret managers, credential masking in agent sandboxes). Status: beta / early adoption; "plain .env will disappear" is speculation, it is still the default everywhere.
- Native `.env` support in runtimes (Node stable 2025; Bun and Deno load env files too, not re-verified this pass). Status: established for Node; others unsourced here.

## Traps (commonly said, now wrong or misleading)

1. "Hidden files are protected/secure." Wrong: on Unix it is just a leading dot; on Windows a toggleable attribute. Malware and AI agents read them freely (s1ngularity, Shai-Hulud).
2. "Dotfiles are hidden on Windows too." Wrong: Windows ignores the dot; `.claude`, `.ssh`, `.env` show in Explorer unless something sets the Hidden attribute (Git for Windows hides only `.git`).
3. "Adding `.env` to `.gitignore` after committing it fixes the leak." Wrong: already-tracked files stay tracked and stay in history; the key must be rotated (GitGuardian: 64% of 2022 leaked secrets still valid in 2026).
4. "GitHub will stop me pushing a secret." Only partly: push protection is default for public repos and only for recognised secret patterns, and can be bypassed; internal/private repos leak more (GitGuardian: ~6x).
5. "`.cursorignore` / telling the AI 'don't read .env' keeps secrets away from the agent." Not guaranteed: Cursor docs say terminal and MCP tools bypass `.cursorignore`; CLAUDE.md is "context, not enforced configuration"; enforcement needs deny rules / sandbox / hooks.
6. "Config files are passive text, safe to clone." Outdated since 2025: `.claude/settings.json` hooks, `.mcp.json`, `.cursor/mcp.json`, rules files have all been used to run code or steal keys on open (CVE-2025-59536, CVE-2026-21852, CVE-2025-54135/54136).

8. "Claude Code only reads CLAUDE.md." Outdated since v2.1.277 (2026-09-18): it reads AGENTS.md when no CLAUDE.md exists.

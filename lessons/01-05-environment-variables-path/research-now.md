# research-now: Environment variables & PATH (as of 2026-10-10)

Lens: the subject as a learner meets it THIS month (October 2026): current mechanisms, names, versions, error texts, and how AI tools now read and shape the environment.
Status tags: **established** / **new this year** (roughly Oct 2025 to Oct 2026) / **beta or announced** / **speculation** / **observed** (seen directly on Aaron's Windows 11 machine on 2026-10-10).
Orchestrator names checked: "Windows Store python alias" = Windows **App Execution Aliases** (`python.exe` / `python3.exe` stubs in `%LOCALAPPDATA%\Microsoft\WindowsApps`); "which python" = `which` / `command -v` / `type -a` on bash/zsh, `where.exe` in cmd, `Get-Command` in PowerShell. All other names in the notes are real and current.

## 1. Environment variables: settings every process inherits from its parent

- Every process carries its own "environment block" of NAME=value pairs; by default a child process inherits a copy of its parent's environment; programs started by the command processor inherit its environment. Status: established. Source: Microsoft Learn, "Environment Variables (Win32)", https://learn.microsoft.com/en-us/windows/win32/procthread/environment-variables (ms.date 2025-07-14).
- Two persistent sources on Windows: user variables (per user) and system variables (everyone). Persistent system values live in the registry key `HKLM\System\CurrentControlSet\Control\Session Manager\Environment`; changing them requires broadcasting `WM_SETTINGCHANGE` so apps "such as the shell" pick them up. A process changing its own variables does not touch the stored ones. Status: established. Same source.
- It is a COPY: a child cannot change its parent's environment. (Mechanism behind "export in one command doesn't survive"; see section 5 for Claude Code saying exactly this.) Status: established. Same source (inheritance by copy); Claude Code docs below.
- Max size of one user-defined variable: 32,767 characters; no technical limit on the whole block since Vista. Status: established. Same source.
- The classic Windows editor is still Control Panel > System > Advanced system settings > Environment Variables (Microsoft's own page still points there; 2026 how-to guides agree; no built-in Settings-app editor found). Status: established. Sources: Microsoft Learn page above; https://geekrewind.com/how-to-add-and-edit-path-environment-variables-in-windows-11/ (2026, undated page).
- PowerToys has had an "Environment Variables" editor since v0.75 (Oct 2023): shows Applied variables in order Profile > User > System, supports switchable profiles. Status: established. Sources: https://learn.microsoft.com/windows/powertoys/environment-variables (Microsoft Learn); https://betanews.com/2023/10/31/microsoft-releases-powertoys-v0-75-0-with-new-environment-variables-module-settings-dashboard-and-more/ (2023-10-31).
- macOS/Linux: variables are set by the shell's startup files (zsh: `~/.zshrc`, `~/.zprofile`; bash: `~/.bashrc`, `~/.profile`); zsh has been the macOS default login/interactive shell since macOS 10.15 (2019). Status: established. Source: Apple Support "Use zsh as the default shell on your Mac", https://support.apple.com/en-us/102360 (published 2026-06-15).
- Env vars are fine for non-secret config, but they are visible to the process owner and every child, end up in crash dumps and debug logs, and on Linux are readable via `/proc/<pid>/environ`; systemd's own docs say environment variables are not suitable for passing secrets. Status: established (argument), sources partly vendor. Sources: https://blog.arcjet.com/storing-secrets-in-env-vars-considered-harmful/ (vendor blog, undated); https://securityboulevard.com/2025/12/are-environment-variables-still-safe-for-secrets-in-2026/ (2025-12); systemd.exec man page (https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html, could not fetch, 403; quote taken via secondary sources, so verify before quoting).

## 2. PATH: an ordered list of folders the shell searches, first match wins

- PATH is just one environment variable: a list of folders (`;`-separated on Windows, `:` on macOS/Linux). When you type a bare name, the shell walks the list left to right and runs the first match. Status: established. Sources: Microsoft Learn `path` command, https://learn.microsoft.com/en-in/windows-server/administration/windows-commands/path ("searches the directories in the command path in the order that they're listed"); PowerShell about_Command_Precedence below.
- Windows builds the effective PATH as **system PATH first, then user PATH appended**. So a tool in a system folder beats the same name in a user folder. Status: established (secondary source; Microsoft's own wording not found this pass). Source: https://itechtics.com/user-vs-system-environment-variables (undated). Observed: on Aaron's machine, `C:\Windows\system32` etc. appear before `C:\Users\soulo\...` entries.
- Windows extension search: `PATHEXT` decides which extensions count as runnable (`.COM;.EXE;.BAT;.CMD;.VBS;.VBE;.JS;.JSE;.WSF;.WSH;.MSC;.CPL` observed), so `python` matches `python.exe`. Status: established. Sources: about_Command_Precedence ("PowerShell treats the file extensions listed in the `$Env:PATHEXT` environment variable as executable files"), https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_command_precedence (ms.date 2026-01-18, PowerShell 7.6 docs). Observed value on Aaron's machine.
- **cmd.exe searches the current folder BEFORE PATH**; PowerShell deliberately does not ("As a security feature, PowerShell doesn't run executable commands ... unless the command is located in a path listed in the `$Env:PATH`"; you must type `.\name`). cmd's behaviour can be switched off with the `NoDefaultCurrentDirectoryInExePath` variable. Status: established. Sources: about_Command_Precedence (2026-01-18); Microsoft Learn `path` command (above); NeedCurrentDirectoryForExePath API docs, https://msdn.microsoft.com/fr-fr/windows/desktop/ms684269.
- PowerShell resolves names in order Alias > Function > Cmdlet > external executable; `Get-Command name -All` lists every match, including hidden ones (e.g. alias `where` vs `where.exe`). Status: established. Source: about_Command_Precedence (2026-01-18).
- "Which program actually ran": bash/zsh `which -a python` / `type -a python` / `command -v python`; cmd `where python`; PowerShell `Get-Command python -All` (first row = the winner). Status: established. Sources: about_Command_Precedence; Observed (all three listed the same three pythons in the same order).
- **Observed, Aaron's machine (2026-10-10):** effective PATH in Git Bash has 60 entries; Machine PATH is 1,064 chars and User PATH 1,226 chars. `python` resolves to three candidates in order: (1) `C:\Users\soulo\AppData\Local\Programs\Python\Python310\python.exe` (wins), (2) `C:\Users\soulo\AppData\Local\Microsoft\WindowsApps\python.exe` (the Store alias stub), (3) `C:\Users\soulo\miniconda3\python.exe`. `py` is `C:\Windows\py.exe` (the legacy launcher). Python310 even appears twice in PATH. Status: observed. A ready-made "first match wins" visual.
- Same observation: the winning Python is **3.10, which python.org now lists as End-of-life (2026-10-01)**. Status: new this year. Source: https://www.python.org/downloads/ (fetched 2026-10-10: 3.10 "End-of-life", end of support 2026-10-01). Note: other sources give Oct 31 2026 as the working date (https://www.herodevs.com/blog-posts/python-3-10-end-of-life-october-2026-security-and-migration-guide); say "October 2026".
- Version managers change PATH on the fly: mise (common pyenv/nvm/asdf successor) either rewrites PATH at every prompt (`mise activate`, recommended for interactive shells) or puts "shims" (tiny stand-in executables) first on PATH; with shims, `which` points at the shim, not the real program. A March 2026 mise release (v2026.3.17) fixed a bug where system binaries earlier in PATH silently shadowed mise tools. Status: established (mise) / new this year (fix). Sources: https://mise.jdx.dev/dev-tools/shims.html (undated docs); https://newreleases.io/project/github/jdx/mise/release/v2026.3.17 (2026-03).

## 3. "Not recognized as a command": the exact messages a learner will see

- **Windows PowerShell 5.1** (the one that ships with Windows), observed verbatim 2026-10-10: `nosuchcmd123 : The term 'nosuchcmd123' is not recognized as the name of a cmdlet, function, script file, or operable program. Check the spelling of the name, or if a path was included, verify that the path is correct and try again.` Status: observed.
- **PowerShell 7.x** (`pwsh`) uses slightly different wording: "...is not recognized as a name of a cmdlet, function, script file, or executable program." Status: established (wording from user reports, not Microsoft docs). Sources: https://kb.netapp.com/data-mgmt/SnapCenter/SC_KBs/SC_Server_for_Linux_powershell_cmdlet_fail_with_the_command_is_not_recognized (undated); JetBrains support thread on PowerShell 7.4.2 (https://intellij-support.jetbrains.com/hc/zh-cn/community/posts/18458399340690/comments/18478257511058, 2024).
- **cmd.exe**, observed verbatim: `'nosuchcmd123' is not recognized as an internal or external command, operable program or batch file.` Status: observed.
- **bash** (Git Bash 5.2.26 observed): `bash: nosuchcmd123: command not found`. **zsh on macOS**: `zsh: command not found: python`. Status: observed (bash) / established (zsh). Source for zsh: https://pydevtools.com/handbook/how-to/how-to-fix-python-command-not-found-on-mac/ (undated).
- Meaning in every case: the name was not an alias/function/built-in and no folder on PATH had a matching file. Causes: not installed; installed but its folder not on PATH; installed and PATH updated but the terminal is older than the change (section 6); typo. Status: established. Sources: about_Command_Precedence; python.org Windows docs troubleshooting (section 4).
- Current PowerShell: 7.6 is the current LTS (GA 2026-03-18, on .NET 10; latest patch seen 7.6.3, 2026-06-16); 7.4 LTS ends support 2026-11-10. Windows still ships Windows PowerShell 5.1 side by side (`powershell.exe` vs `pwsh.exe`), so learners meet both error wordings. Status: new this year. Sources: https://devblogs.microsoft.com/powershell/announcing-powershell-7-6/ (2026-03-18); https://feed.nuget.org/packages/PowerShell/7.6.3 (2026-06-16); https://eosl.date/eol/product/powershell/ (undated). Observed: `pwsh` is not installed on Aaron's machine.

## 4. Python on Windows this month: Store alias, install manager, `py`

- Windows ships **App Execution Aliases**: stub `python.exe` and `python3.exe` in `%LOCALAPPDATA%\Microsoft\WindowsApps`, present even when no Python is installed. With no arguments the stub opens the Microsoft Store; with arguments it errors. `where python` finds it, so "found on PATH" does not mean "Python installed". Status: established. Sources: https://swi-prolog.discourse.group/t/is-python-exe-real-on-windows-11/9524 (undated forum); https://learn.microsoft.com/en-us/answers/questions/2180769/how-can-i-disable-the-microsoft-store-python-app-e (2025-02; no Group Policy found to stop them); toggle at Settings > Apps > Advanced app settings > App execution aliases.
- Python's docs: the `WindowsApps` PATH entry is included once by default "after other user paths". That is why a real install placed earlier in user PATH beats the stub (observed on Aaron's machine), and why a missing/late install lets the stub win. Status: established. Source: "Using Python on Windows", https://docs.python.org/3/using/windows.html (Python 3.15 docs, fetched 2026-10-10).
- **Python install manager** is now the CPython team's recommended way to get Python on Windows (Store or python.org; identical). Commands: `python` (active venv, or default runtime), `py` (recommended when several runtimes; `py install 3.14`, `py list`, `py -V:3.14`), `pymanager` (unambiguous alias of `py`), `python3` (included only to catch POSIX habits, "not meant to be widely used"). Adding `%LocalAppData%\Python\bin` to PATH is optional. Status: new this year (default since Python 3.14, Oct 2025). Source: docs.python.org/3/using/windows.html (3.15 docs).
- The traditional full python.org installer is "deprecated since 3.14 and will not be produced for Python 3.16 or later"; the old `py.exe` launcher is deprecated too, and an old launcher still installed can take priority over the new `py` (python.org advises uninstalling "Python launcher"). Status: new this year. Same source. Observed: Aaron still has the legacy `C:\Windows\py.exe` and a classic Python310 install.
- Latest versions: Python 3.15.0 released 2026-10-09 (delayed a week from Oct 1 by a third release candidate); 3.14 is in bugfix; install manager latest stable seen 26.1 (2026-03-31), 26.3 listed in an Aug 2026 guide; 26.3b1 (2026-06-04). Status: new this year. Sources: https://www.python.org/downloads/ (fetched 2026-10-10); https://www.python.org/downloads/release/python-3150rc3/ (2026-09); https://www.python.org/downloads/release/pymanager-261/ (2026-03-31); https://www.python.org/downloads/release/pymanager-263b1/ (2026-06-04).
- Python's own troubleshooting table names the exact symptoms: `python` opens the Store (check aliases); `py` says "can't open file" (legacy launcher priority); `python` and `py` launch different runtimes (conflicting installs / PATH order). Status: new this year (docs for install manager). Source: docs.python.org/3/using/windows.html.
- macOS: there is no `python` command by default, only `python3` (Apple removed the Python 2 `python` in macOS 12.3, 2022; `/usr/bin/python3` comes with Xcode Command Line Tools). Homebrew on Apple Silicon lives in `/opt/homebrew/bin`, which is only on PATH after the `brew shellenv` line is added to `~/.zprofile`/`~/.zshrc` (the installer prints this step; easy to miss). Status: established. Source: https://pydevtools.com/handbook/how-to/how-to-fix-python-command-not-found-on-mac/ (undated); https://www.freecodecamp.org/news/how-to-fix-python-installation-errors-on-mac/ (undated).

## 5. Virtual environments prepend to PATH (and modern tools skip activation)

- Activating a venv "will prepend that directory to your PATH, so that running python will invoke the environment's Python interpreter"; it also sets `VIRTUAL_ENV`. Activation is optional: you can call the venv's interpreter by full path. `VIRTUAL_ENV` "cannot be relied upon" to tell if a venv is in use. Status: established. Source: https://docs.python.org/3/library/venv.html (3.15 docs, fetched 2026-10-10).
- Since Python 3.13, `venv` writes a `.gitignore` inside the env so the whole folder is ignored by git. Status: established. Same source.
- Activation is per terminal: it changes only that shell's copy of PATH, so a second terminal (or an agent's separate shell) is NOT in the venv. Status: established. Follows from section 1; venv docs.
- `uv` (Astral): `uv run` runs commands in the project's `.venv` without activating anything; the env is "isolated from the current shell by default", so plain `python -c "import example"` fails while `uv run` works. Status: established. Source: https://docs.astral.sh/uv/concepts/projects/run/ (updated 2025-10-24); https://handbook.eng.kempnerinstitute.harvard.edu/s1_high_performance_computing/development_and_runtime_envs/using_uv_env.html (undated). Observed: uv is on Aaron's PATH via a WinGet package folder.
- Install manager's `python` command picks "the active virtual environment" first when one is active. Status: new this year. Source: docs.python.org/3/using/windows.html.

## 6. Why a new terminal is needed after an install

- A running process got its environment when it started; later edits to the stored (registry or profile-file) values don't reach it. `setx` docs: values "are available in future command windows only, not in the current command window." Status: established. Source: https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/setx (updated 2026-02-16).
- Who gets the new value: only processes started after the change, from a parent that itself has the new value. Explorer listens for `WM_SETTINGCHANGE`; terminals already open, and apps launched from them, do not refresh. Status: established. Source: Win32 Environment Variables page (2025-07-14).
- WinGet still does not refresh PATH in the open terminal: the 2023 feature request (microsoft/winget-cli #3077) to do so is still open as a feature request; WinGet itself only adds PATH entries for portable/zip packages, other installers write their own. Status: established (still true in 2026). Sources: https://github.com/microsoft/winget-cli/issues/3077 (2023, open); https://github.com/microsoft/winget-cli/issues/2815; https://curatedsql.com/2026/06/01/winget-and-path-not-updating/ (2026-06-01).
- VS Code: its integrated terminals inherit VS Code's own environment, so after a system PATH change the terminal stays stale until VS Code is restarted; extensions that change terminal env vars trigger a "relaunch the terminal" prompt (`terminal.integrated.environmentChangesRelaunch`, default true). The Claude Code VS Code extension had a related bug (env contributions registered too late) resolved May 2026. Status: established / new this year (bug). Sources: https://github.com/microsoft/vscode/issues/240098 (2025); https://claudeissues.com/issue/55486-claude-code-vs-code-extensions-env-var-contributions-are-registered-too-late-cau (2026, mirror of GitHub issue).
- macOS/Linux equivalent: edits to `~/.zshrc` apply to new shells (or after `source ~/.zshrc`); version-manager shims disappear "until you open a new terminal". Status: established. Source: pydevtools.com (above).
- Agents too: "Claude Code reads shell environment variables at startup, so changes to them take effect the next time you launch `claude`." Status: established (current docs). Source: https://code.claude.com/docs/en/env-vars (fetched 2026-10-10, undated page).
- `setx` caps values at 1,024 characters and truncates silently, which can destroy a long PATH. Observed: Aaron's user PATH is 1,226 chars, so `setx PATH ...` would cut it. Status: established + observed. Source: setx docs (2026-02-16).

## 7. Secrets in env vars and `.env` files

- Convention: `.env` = `KEY=value` lines at a project root, loaded into the process environment at start. No formal spec; each runtime defines its own. Status: established. Source: Node.js docs, https://nodejs.org/api/environment_variables.html ("there is no formal specification for it").
- SDKs read keys from env vars by default: OpenAI Python SDK `OpenAI()` uses `OPENAI_API_KEY` ("This is the default and can be omitted"; README recommends python-dotenv "so that your API key is not stored in source control"); Gemini SDKs auto-detect `GEMINI_API_KEY` or `GOOGLE_API_KEY` and if both are set `GOOGLE_API_KEY` wins; Anthropic tools use `ANTHROPIC_API_KEY`. Status: established. Sources: https://github.com/openai/openai-python (README, fetched 2026-10-10); https://ai.google.dev/gemini-api/docs/api-key (current docs); Claude Code env-vars page (below).
- Node.js reads `.env` natively: `node --env-file=.env` (added v20.6.0; "no longer experimental" as of v24.10.0 / v22.21.0, Oct 2025), plus `--env-file-if-exists` and `process.loadEnvFile()`. If a variable is in both the real environment and the file, **the real environment wins**. Status: new this year (stable). Source: https://nodejs.org/api/cli.html (fetched 2026-10-10).
- Bun auto-loads `.env`, `.env.<NODE_ENV>`, `.env.local` with no flag (disable with `--no-env-file` or `env = false` in bunfig.toml). So "my program saw a key I never set" can be the runtime loading a file. Status: established. Source: https://bun.com/docs/runtime/environment-variables (current docs).
- Python still has no built-in `.env` loader (python-dotenv library). Status: established. Source: openai-python README.
- Leak scale: GitGuardian State of Secrets Sprawl 2026: 28.65M new hardcoded secrets on public GitHub in 2025 (+34%); AI-service secrets +81%; 24,008 unique secrets in MCP config files; Claude-Code-co-authored commits leaked at 3.2% vs 1.5% baseline. Status: new this year (vendor report). Sources: https://thehackernews.com/2026/03/the-state-of-secrets-sprawl-2026-9.html (2026-03); https://dev.to/gitguardian/the-state-of-secrets-sprawl-2026-ai-service-leaks-surge-81-and-29m-secrets-hit-public-github-2bgj (2026).
- GitHub push protection blocks recognised secrets on pushes to public repos by default since early 2024 (user can bypass). Status: established. Source: https://github.blog/news-insights/product-news/keeping-secrets-out-of-public-repositories/ (2024-02-29).
- `.gitignore` only controls commits, not what an agent or program reads. Status: established. Source: https://infisical.com/blog/your-ai-coding-agent-is-reading-your-env-file (2026-04-09, updated 2026-07-03; vendor post, claims partly illustrative).

## 8. Why AI agents and tools read env vars (and how vendors now fence it)

- Agents run commands in child shells, so those commands inherit the agent's environment, including any keys exported in the terminal you launched it from. Status: established. Sources: Win32 inheritance (section 1); Claude Code env-vars page: `CLAUDECODE=1` is "Set ... in subprocesses Claude Code spawns (Bash and PowerShell tools, ... stdio MCP server subprocesses)".
- **Claude Code** (current docs, fetched 2026-10-10):
  - `ANTHROPIC_API_KEY`: "When set, this key is used instead of your Claude Pro, Max, Team, or Enterprise subscription even if you are logged in"; in `-p` mode "always used when present"; interactive mode asks once. Real billing trap: a forgotten exported key silently switches you to pay-per-use. `/status` shows which credential is active. Status: established. Source: https://code.claude.com/docs/en/env-vars.
  - Settings files have an `env` block; its values replace the inherited shell value; "Claude Code copies these values ... as written. No shell processes them" (so `~`/`$HOME` aren't expanded). Status: established. Same source.
  - Bash tool: "Environment variables don't persist. An `export` in one command won't be available in the next." "Activate your virtualenv or conda environment before launching Claude Code", or use `CLAUDE_ENV_FILE` / a SessionStart hook. At session start it sources `~/.zshrc`/`~/.bashrc`/`~/.profile` to capture aliases and functions. Status: established. Source: https://code.claude.com/docs/en/tools-reference (fetched 2026-10-10).
  - `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` strips credentials (by name or value) from Bash commands, hooks and stdio MCP servers; `CLAUDE_CODE_MCP_ALLOWLIST_ENV=1` starts MCP servers with only a safe baseline env plus their configured `env`. Both opt-in. Status: new this year. Source: env-vars page.
  - Example deny rule in docs: `"Read(./.env)"`, `"Read(./.env.*)"` to stop Claude reading `.env`. Status: established. Source: https://code.claude.com/docs/en/settings (fetched 2026-10-10).
  - `.mcp.json` supports `${VAR}` and `${VAR:-default}` expansion in `command`, `args`, `env`, `url`, `headers`, so a shared config can reference a key instead of containing it; an unset var stays as literal `${VAR}` text with a warning in `claude mcp list`. Status: established. Source: https://code.claude.com/docs/en/mcp (fetched 2026-10-10).
  - Historic bug reports (late 2025) of Claude Code loading a project's `.env` into its command environment (v2.0.55 era), issues since closed. Status: established as history; current behaviour unverified, do not claim either way. Sources: https://claudeissues.com/issue/16619-bug-env-file-automatically-loaded-into-bash-environment-for-tool-calls; https://claudeissues.com/issue/3403-bug-unexpected-loading-of-projects-env-file-when-executing-shell-commands.
- **OpenAI Codex**: `shell_environment_policy` in `config.toml` controls which env vars reach commands Codex runs (`inherit = "none"` or `"core"`, filters, `set`). Current docs: `ignore_default_excludes` "defaults to `true`, so Codex doesn't automatically remove variable names containing `KEY`, `SECRET`, or `TOKEN`"; set it to `false` to turn that filter on. Status: new this year (default changed; older 2025 guides and early PRs say the filter was ON by default). Sources: https://learn.chatgpt.com/docs/config-file/config-advanced and .../config-basic (fetched 2026-10-10, undated); contrasting older guide https://codex.danielvaughan.com/2026/04/28/codex-cli-shell-environment-policy-subprocess-secrets-defence/ (2026-04-28). Hedge: "recent Codex versions pass keys through unless you configure them not to".
- **GitHub Copilot cloud (coding) agent**: secrets/variables you add as repository/org "Agents" secrets are exposed to the agent as environment variables, except those prefixed `COPILOT_MCP_`, which only MCP servers get; older "copilot" Actions-environment secrets were auto-migrated. Status: new this year. Sources: https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/configure-secrets-and-variables; https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers (current docs, undated).
- Agents also read `.env` as an ordinary file and send what they read to the model provider as context; Sonar's canary test found a `.env` key verbatim in agent traffic. Status: new this year (reports; vendor sources). Sources: https://www.sonarsource.com/blog/your-secrets-are-leaking-to-ai-coding-agents/ (2026); Infisical post (2026-04-09).
- Claude Code transcripts store whatever a tool read (a printed key lands in `~/.claude/projects/...jsonl`, unencrypted). Status: established. Source: https://code.claude.com/docs/en/claude-directory (per 01.04 research, fetched 2026-10-09).

## 9. Where it is heading (secrets out of plain env/.env)

- Direction stated across 2026 security writing: remove static keys from developer machines, fetch from a secrets manager at run time, short-lived auto-rotated credentials, one scoped identity per agent, treat agent keys as non-human identities. Status: beta or announced (direction) / speculation (pace). Source: https://thehackernews.com/2026/09/secrets-sprawl-is-identity-problem-that.html (2026-09-24, sponsored by Keeper Security; Keeper RSAC 2026 survey: 46% say AI tools can reach critical systems).
- 1Password Environments: "Local .env file" destination that mounts `.env` without plaintext on disk (Mac/Linux only), SDK/CLI read access (Feb 2026), Cursor integration, hook to validate mounted `.env` for Cursor/GitHub Copilot; public beta since 2025-10-29, no GA announcement found. Status: beta. Sources: https://www.1password.dev/environments (current docs); https://1password.com/blog/1password-environments-env-files-public-beta (2025-10-29); https://www.1password.community/developers-blog-53/developer-newsletter-february-2026-24072 (2026-02).
- Runtime injection CLIs (`infisical run`, `op run`, dotenvx encrypted `.env`) put keys in the child's environment only for the run. Status: established tools, growing use. Sources: Infisical post (2026-04-09); https://dotenvx.com (undated).
- Agent-specific env fencing (Claude Code scrub/allowlist flags, Codex env policy, Copilot `COPILOT_MCP_` split) is the new layer of 2025-26; expect defaults to keep tightening. Status: new this year (features) / speculation (future defaults).

## Traps (commonly said, now wrong or misleading)

1. "If `where python` finds it, Python is installed." Wrong on Windows: the WindowsApps Store stub is on PATH by default and opens the Store. (docs.python.org/3/using/windows.html; Microsoft Q&A 2025-02)
2. "Download Python from python.org with the big installer and tick 'Add to PATH'." Outdated: the full installer is deprecated since 3.14 and ends at 3.16; the recommended path is the Python install manager and the `py` command. (docs.python.org, 3.15 docs)
3. "Python 3.10 is a safe default." It reached end-of-life in October 2026. (python.org downloads, 2026-10-10)
4. "Type `python` on a Mac." Default macOS has only `python3`. (pydevtools.com)
5. "You have to activate the venv to use it." Activation is optional (full path, or `uv run`); and activation only affects that one terminal. (Python venv docs; uv docs)
6. "Installing fixed PATH, so it works now." Only for terminals opened after the change, and inside VS Code only after VS Code restarts; WinGet still doesn't refresh the open terminal. (setx docs 2026-02; winget-cli #3077)
7. "Just `setx PATH %PATH%;C:\new`." Truncates at 1,024 chars and expands variable references; long PATHs get damaged. (setx docs)
8. "Your user PATH entry will override the system one." Windows puts system PATH first; the system copy wins. (itechtics; observed)
9. "Codex automatically hides KEY/SECRET/TOKEN variables." Current docs say that filter is OFF by default (`ignore_default_excludes = true`); older guides say otherwise. (learn.chatgpt.com config docs, 2026)
10. "Being logged into Claude means you're on your subscription." An exported `ANTHROPIC_API_KEY` takes over (after one approval interactively, always in `-p`). (code.claude.com/docs/en/env-vars)
11. "`.gitignore` keeps `.env` safe." It only keeps it out of commits; agents, tools and runtimes (Bun auto-load) still read it, and agent transcripts can store it. (Infisical 2026; Bun docs; Claude Code docs)
12. "Node needs the dotenv package." Node reads `.env` natively and stably since v24.10/v22.21 (`--env-file`), and real env vars beat the file. (nodejs.org/api/cli.html)
13. "An agent's `export FOO=...` or `source .venv/bin/activate` sticks for the session." In Claude Code each Bash command gets a fresh environment; exports don't persist. (code.claude.com/docs/en/tools-reference)
14. "PowerShell runs `script.ps1` from the current folder like cmd does." It doesn't; you need `.\`. cmd does search the current folder first. (about_Command_Precedence 2026-01-18)
